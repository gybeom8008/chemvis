# 실험실: Astra와 정한 것

상태: 합의 · 2026-11-11 · 기준 커밋 `56ea710` · [기획안 개요](../../../docs/plan/README.md)

[인계서](../../../docs/plan/handover.md) 8.3의 여섯 가지를 Astra(설계)와 Claude(표현·엔진·구현)가 두 차례 주고받아 정했다. Astra의 설계서 원문은 [lab-astra.md](lab-astra.md), 단계 1의 자료 행은 [lab-rows-stage1.md](lab-rows-stage1.md)다. 이 문서가 설계서와 다르면 이 문서를 따른다. [lab-review.md](lab-review.md) 4절 이후의 의견은 이 문서로 대체한다.

실험실 구현은 아직 보류다. 윤범님이 반응 표현을 확정한 뒤에 시작한다. 이 문서는 그때 바로 시작할 수 있게 정해 둔 것이다.

## 1. 한눈에

| | 정한 것 |
|---|---|
| 분자 조립 | 실험실 안에 따로 둔다. 원자 모형을 이어 분자 구조를 조립하는 화면이고, 반응이 일어난다고 말하지 않는다 |
| 조건 | "25 °C의 묽은 물속" 하나로 고정. 고르는 화면은 없다 |
| 화면의 글 | 무대에 한 줄, 결과에 제목 한 줄. 나머지는 '자세히' |
| 금속 | 원자 6개로 된 조각. 표면 원자 하나가 반응한다 |
| 침전 | 첫 쌍부터 옅은 각진 판 위에 놓인다. 다음 쌍은 같은 판에 더해진다 |
| 검토 | 자료를 쓴 모델과 다른 모델이 원문과 대조하고 기록을 남긴다. 전문가 검토라고 하지 않는다 |
| 엔진 | `compileFrom`(있던 상태에서 이어서 컴파일), `precipitate using a b [onto s]`(고른 이온만 침전) |

## 2. 분자 조립

- 주장은 **"원자 모형을 연결해 분자 구조를 조립해요."** 하나다. 물속 배경과 온도 표시가 없는 작업판을 쓴다.
- 원소는 H, C, N, O, F, Cl. 조립용 전자(비공유 전자쌍, 홑전자)는 H (0,1), C (0,4), N (1,3), O (2,2), F·Cl (3,1). 이것을 실제 낱원자의 전자 상태라고 설명하지 않는다.
- 결합은 양쪽에 홑전자가 하나씩 남아 있을 때만 만든다. 단일·이중·삼중 결합까지. 비공유 전자쌍을 뜯어 쓰지 않는다.
- 형식 전하가 0인 구조만. 고리는 첫 판에서 뺀다(같은 분자 안에서 새로 잇는 조작을 막는다).
- **O 원자 둘로 O₂를 완성하는 조작은 막는다.** 실제 산소 분자에는 홑전자가 둘 있는데 이 모형으로는 그릴 수 없기 때문이다. 문구: "산소 분자의 실제 홑전자 두 개는 이 조립 모형으로 정확히 나타낼 수 없어요."
- 이름을 붙이는 분자(연결 구조를 대조한 것만): H₂, N₂, F₂, Cl₂, HF, HCl, H₂O, NH₃, CH₄, CO₂, H₂O₂, CH₃OH, C₂H₅OH, C₂H₄, CH₃COOH. 분자식이 아니라 그래프로 대조한다.

| 결과 | 문구 |
|---|---|
| 대조한 구조와 같음 | "물 분자 모형을 조립했어요." |
| 전자가 모두 짝지어졌지만 목록에 없음 | "전자 표시는 모두 짝지어졌어요. 실제로 있는 분자인지는 아직 확인하지 않았어요." |
| 홑전자가 남음 | "이 모형에는 짝을 이루지 않은 전자가 남아 있어요." |

- 조립한 분자를 수용액 반응의 재료로 넣는 것은 그 재료가 등록되어 있을 때만 된다(단계 1에서는 H₂O, NH₃). 새 인스턴스를 넣는 편집이고 반응 장면을 재생하지 않는다.
- 조립에서는 다가갈 때의 +, − 표시(`pulls`)를 끈다.

## 3. 조건과 글

- 환경은 `water / 25 °C / ordinary / none`으로 고정한다. 자료 행에는 네 필드와 활동도 참고 구간(10⁻³–10⁻²)을 그대로 둔다. 다른 조건이 들어오면 조용히 바꾸지 않고 지원하지 않는다고 답한다.
- 무대의 한 줄: **"입자 몇 개로 반응 한 번을 봐요."** 조건 표시: "25 °C의 묽은 물속".
- '자세히'의 첫 두 문장: "화면의 입자는 수많은 입자를 대표해요. 입자 수는 농도나 반응한 비율이 아니에요."
- 바로 보여야 하는 것: 지금 모드, 조건, 결과 제목, 모자란 재료("Ag⁺ 1개가 더 필요해요"), "구조만 보기" 구분, 실행 실패. 그 밖의 까닭·출처·한계는 '자세히'로 간다.
- 부정의 제목은 무엇을 부정하는지 적는다("이 조건에서는 새 고체가 생기지 않아요"). "아무 일도 일어나지 않아요"는 쓰지 않는다.
- 규칙 충돌과 그리기 실패는 화학적 모름과 섞지 않고 "장면을 정확히 만들지 못했어요"로 따로 알린다.
- '전부 반응했어요', 수율, 평형 도달 같은 표시는 만들지 않는다.

## 4. 고체를 그리는 방법

반응 표현의 일이기도 하다. 2026-11-11에 비교 화면에 만들었다('침전', '금속 조각' 장면). 엔진 명령은 `precipitate using a b [onto s] [as s]`, `metal`, `land`, `join`, `leave`다. `compileFrom`(E1)과 `addSpecies`는 Astra가 구현했다(검사는 `tests/unit/compile-from.test.ts`의 33개).

**금속 조각**

1. 원자 6개를 두 줄로 놓고 조각 전체를 하나의 표면으로 감싼다. 여섯 개 모두 실제 ID가 있는 재고다. 원자 사이에 전자쌍 주머니를 그리지 않는다.
2. 금속 이온이 반응할 표면 원자 옆에 와서 닿는다. Ag⁺ 둘은 서로 다른 자리에 닿는다.
3. 그 표면 자리에서 전자 점 두 개가 드러나고, 같은 점이 하나씩 이온으로 건너간다. 점을 감싸는 주머니나 테두리는 그리지 않는다(금속의 전자는 조각 전체에 퍼져 있다).
4. 전하는 전자 하나마다 바뀐다. 내주는 원자는 전자가 떠날 때, 받는 이온은 도착할 때.
5. 중성이 된 원자는 닿아 있던 표면에 그대로 붙어 조각의 일부가 된다. 원소는 구별해서 그린다.
6. 전자 둘을 내준 원자는 조각에서 떨어져 물에 둘러싸인다. 2–6은 한 번의 조작이고 중간에 멈춘 상태를 남기지 않는다.

**아연 조각에 붙은 구리는 따로 떨어진 구리 조각으로 다루지 않는다.** 아연이 남아 있는 조각에 Ag⁺를 가져가면 아연도 전자를 줄 수 있으므로 판정은 모름(경쟁 경로)이다.

**이온 결정**

- 모든 이온 결정(소금 결정, 침전) 뒤에 옅은 각진 판을 하나 깐다. 판은 "이 이온들은 한 고체다"라는 표시이고 특정 결정면이나 분자 테두리가 아니다.
- 침전의 첫 쌍부터 판이 생긴다. 다음 쌍은 같은 판에 붙고 판이 넓어진다. 녹으면 줄고, 이온이 없으면 사라진다.
- 이온의 전하는 그대로다. 이온 사이에 전자쌍 주머니를 그리지 않는다. 화면 밖의 이온을 지어내서 큰 결정처럼 꾸미지 않는다.
- 재료 세트 "고체가 생기기"는 Ag⁺와 Cl⁻를 세 쌍 준다. 한 번의 조작은 고른 한 쌍만 쓴다.

## 5. 검토

- Astra가 자료 행과 출처를 쓰고, Claude가 원문 페이지를 열어 값을 대조하고 유도값을 다시 계산한다. 값뿐 아니라 "이 조건에서 이 사건을 이렇게 그려도 되는가"까지 본다.
- 행마다 기록을 남긴다(형식은 [lab-rows-stage1.md](lab-rows-stage1.md) 8.2). 숫자·조건·맥락 목록·생성물·템플릿이 바뀌면 이전 대조는 무효다. 이견이 남은 행은 `draft`로 두고 실행하지 않는다.
- 앱의 출처 화면: "출처와 대조한 자료이고 전문가가 검토한 것은 아니에요."

## 6. 엔진

### E1: 있던 상태에서 이어서 컴파일

```ts
type CompileFromResult =
  | { timeline: Timeline; end: World; effects: EngineEffect[]; errors: []; warnings: Diag[] }
  | { timeline: null; end: null; effects: []; errors: Diag[]; warnings: Diag[] };

export function compileFrom(base: World, stage: StageDef, steps: string, opts?: { title?: string }): CompileFromResult;
```

- `base`를 바꾸지 않는다. `timeline.initial`은 `base`의 복사본이고 배치를 다시 하지 않는다. `end`는 마지막 단계의 끝 상태를 복사한 것이다.
- 한 단계라도 오류가 나면 전부 버린다.
- `step` 블록만 받는다. 재료를 만드는 명령(`mol`, `place`, `load`, `crystal`, `crowd`)은 단계 안에서도 거부한다. 실험실은 쓸 수 있는 명령의 목록을 따로 둔다.
- 이름·번호·결정·수화·렌즈를 그대로 이어받는다. 새 이름은 있는 원자 ID, 선언 이름, 결정 이름과 겹치지 않게 붙인다(원자 ID는 `이름.기호`라서 `counter`만 이어서는 겹침을 막지 못한다).
- 단계가 끝날 때의 자리 정리(`separateSolutes`, `resolveOverlaps`, `keepInside`)는 반응에 낀 입자와 필요한 물만 움직인다. 관계없는 입자와 있던 고체는 그 자리에 둔다.
- 난수는 입력(World, 무대, 단계)과 엔진 버전에서 정한다. 같은 입력이면 같은 타임라인이다. 제목은 배치에 영향을 주지 않는다.
- `effects`는 새로 생긴 결정의 이름, 더해진 원자, 있던 결정에 붙였는지를 알려 준다. 실험실이 이름을 추측하지 않게 한다.
- 재료 넣기는 `addSpecies`로 따로 한다. 이것도 입력을 바꾸지 않고, 더한 원자의 ID와 오류를 돌려준다. 금속 조각과 결정은 실험실의 재료 계층이 만든다.

### E2: 고른 이온만 침전

```text
precipitate using a b [onto s]
```

- `a`는 양이온, `b`는 음이온의 선언 이름이다. 이름을 못 찾으면 화학식으로 대신 찾지 않고 오류다.
- 둘 다 결합이 없는 단원자 이온이고, 전하의 부호가 반대이고 크기가 같아야 한다. 배경 물, 전극, 다른 결정에 든 것은 거부한다. 수화 껍질이 있는 것은 된다.
- `onto`는 비어 있지 않은 같은 염의 결정만 된다. 없으면 겹치지 않는 새 이름을 붙이고 `effects`로 알린다.
- 검사를 모두 마친 뒤에 수화 풀기, 이동, 결정 소속을 한꺼번에 바꾼다. 전자·전하·결합은 바뀌지 않는다.

### 입자를 가리키는 방법

| | 뜻 |
|---|---|
| 원자 ID | 반응을 지나도 그대로인 원자 하나 |
| `{ instanceId, revision }` | 지금 집을 수 있는 입자 하나. 반응하면 새 인스턴스가 되고 원자 ID로 앞의 것과 이어진다 |
| `aggregateId` | 결정, 금속 조각처럼 함께 움직이는 묶음 |

`owner`는 처음 선언한 이름이고 고쳐 쓰지 않는다. `a.H1`이 NH₃로 가면 그 원자는 계속 `a.H1`이다(`b.H4`가 아니다). 다음 반응의 자리는 지금의 그래프에서 찾고, 찾은 원자 ID를 대본에 적는다.

실행 취소는 World와 함께 입자 목록, 고체 묶음, 선반, 이름 발급 상태를 되돌린다. `revision`은 되돌려도 줄지 않는다.

### 검사를 두는 곳

- 엔진: 끊긴 참조, 전자 수, 반쪽 결합, 결정 소속의 중복, 쓸 수 없는 명령.
- 실험실(계획과 대조): 원자 ID마다의 원소, 반응에 낀 원자의 집합, 총전하, 모형 전자 수(`2Σlp + Σrad + 2Σ결합 차수`), 기대한 생성물의 그래프·상·묶음, 관계없는 입자가 그대로인지.
- 수화하면서 새로 그린 배경 물은 재고와 따로 적는다.

### 금속에 더 필요한 것

`hop`은 전자 장부만 바꾼다. 조각에서 빠지고 붙는 일(상, 묶음, 표면 자리, 전자 점이 드러나고 숨는 시점)은 새 기능이다. 이것이 없으면 R01–R03은 실행하지 않는다.

## 7. 설계서에서 고치는 것

- `shifts`는 반응 앞뒤에 전자쌍이 어디에 있는지를 그리는 기능이다. 반응 경로가 검증됐다는 뜻이 아니다. 축합·가수분해는 실험실 목록에 넣지 않는다.
- `pulls`의 +, −는 그리는 쪽이 어림한 것이다. 판정에 쓰지 않는다.
- 전극의 전자 경로(`free`, `plateSlot`)를 물속 금속 조각에 그대로 쓸 수 있다고 가정하지 않는다.
- 그림에서 전자를 생략하는 것과 World에서 전자가 없어지는 것은 다르다. 결정에 들어가고 나올 때도 지킨다.

## 8. 단계 0에서 통과해야 하는 것

구현을 시작할 때 가장 먼저 한다. 대본과 기대 끝 상태는 [lab-rows-stage1.md](lab-rows-stage1.md) 7절에 있다.

| 시험 | 기대 |
|---|---|
| 있던 상태 보존 | A01 재료를 아무 데나 옮긴 World에서 단계만 컴파일하면 `initial`이 입력과 같고 `base`는 그대로다 |
| 이어서 세 번 | 생성물의 ID와 자리가 이어지고 새 ID가 겹치지 않는다. 같은 입력이면 타임라인이 같다 |
| 같은 H를 두 번 | H₃O⁺ → NH₃ → OH⁻. 둘째 반응은 NH₄⁺에 붙어 있는 `a.H1`을 찾아 쓴다. 전자 24개, 총전하 0 |
| 고른 이온만 침전 | Ag⁺ 셋, Cl⁻ 셋에서 `using a3 b2` → 결정에는 그 둘만 있다 |
| 결정이 자람 | `onto`로 두 번 더 → 같은 결정의 이온이 2, 4, 6개 |
| 잘못된 대상 | 같은 이온 두 번, 이미 결정에 든 이온, 다른 염의 결정 → 실패하고 아무것도 바뀌지 않는다 |
| 금속 조각 | Zn 여섯 + Ag⁺ 둘 → Zn 하나만 이온이 되어 나가고 조각에는 Zn 다섯과 Ag 둘. 전자 12개, 총전하 +2 |
| 재료 부족 | Ag⁺가 하나뿐 → 반응은 하지만 재료가 모자람. 전자도 전하도 그대로 |
| 도중 취소 | 첫 전자가 건너간 뒤 취소 → 끌기 전 상태 그대로. Zn⁺나 중성 Ag가 남지 않는다 |
| 생성물 다시 쓰기 | 생긴 물 둘을 맞대면 "얼마나 반응하는지는 계산하지 않아요". 생긴 AgCl을 물에 대도 같다 |
| 계획과 다른 대본 | `a.H1`을 옮기기로 했는데 대본이 `a.H2`를 옮기면 컴파일이 되어도 실패다 |

화면도 따로 본다. 첫 침전부터 고체로 읽히는지, 금속에서 원자가 떨어지고 다른 금속이 붙는 것이 보이는지를 처음·중간·끝 캡처와 `npm run flicker`로 확인한다.

## 10. Astra를 부르는 방법

이 컴퓨터에는 Codex 데스크톱 앱이 있고, 그 안의 `codex` 실행 파일을 `%USERPROFILE%\.local\bin\codex.cmd`가 불러 준다. 기본 모델이 Astra다. Claude Code의 codex 플러그인은 이 경로를 찾지 못하므로 직접 부른다.

```bash
~/.local/bin/codex.cmd exec -s read-only -o answer.md - < prompt.md
```

```bash
~/.local/bin/codex.cmd exec resume <세션 번호> -c 'sandbox_mode="workspace-write"' -o answer.md - < prompt.md
```

첫째는 읽기만 하는 새 대화, 둘째는 앞의 대화를 이어 가며 파일을 쓰게 하는 것이다. 세션 번호는 첫 실행의 출력 맨 위에 나온다. 2026-11-11의 대화는 `01a1c8f6-3870-7a73-9dd4-5cf97b76b73a`다. 답이 오기까지 10분쯤 걸리므로 뒤에서 돌려 두고 다른 일을 한다.
