# 단계별 반응열 계산

2026-11-16 작업 트리에서 계산했다. 화면 효과는 연결하지 않았다. 구현은 [enthalpy.ts](../../src/chem/enthalpy.ts), 검사는 [enthalpy.test.ts](../../tests/unit/enthalpy.test.ts)에 있다.

## 계산 방법과 단위

표준 생성 엔탈피는 원소를 기준 상태에서 모아 물질 1몰을 만들 때 드나드는 열이다. 표는 298.15 K 값이며 단위는 kJ/mol이다. 단계 계산은 `Σ(개수 변화 × 생성 엔탈피)`이다. 음수는 발열, 양수는 흡열을 뜻한다.

`stepEnthalpy`는 화면에 그린 분자 수를 그대로 계수로 쓴다. 반응식 한 번으로 나누거나 제한 반응물을 찾아 정규화하지 않는다. 호출 결과는 요청한 **화면 계수 기준 kJ 척도**이다. 실제 분자 두세 개가 수십 kJ를 낸다는 뜻은 아니다. 실제 분자 수를 줄 단위로 바꾸려면 아보가드로 수로 나눠야 한다. 화면 효과에는 이 환산을 하지 않는다.

결합으로 이어진 원자 묶음마다 `formulaOf`를 호출한다. 예를 들어 에탄올은 `C2H6O`, 아세트산은 `C2H4O2`, 아세트산 이온은 `C2H3O2-`, 글라이신은 `C2H5NO2`이다. 생성 엔탈피 표에는 별칭을 중복해서 넣지 않았다. 결정 전체는 분자가 아니므로 이온 종류에서 얻은 염 이름(`NaCl`, `CaCO3` 등)을 사용한다.

앞뒤에서 화학식과 상이 같고 개수도 같으면 표를 찾기 전에 지운다. 이 때문에 모르는 이온이 그대로 있는 단계도 0이다. 값이 없는 항이 실제로 변하면 `dH: null`이며 `missing`에 화학식을 넣는다. `terms`에는 계산할 수 있었던 항만 남는다. null일 때 `terms`만 더해서 반응열로 쓰면 안 된다.

`estimated`는 결합 엔탈피 어림값을 사용했다는 뜻이다. `checked`는 자료 원문을 대조했는지를 뜻한다. 서로 다른 표시이다. **estimated:false라도 checked:false인 잠정 자료가 포함될 수 있다.** 자료 상태는 `FORMATION_ENTHALPIES`에서 화학식과 상으로 조회할 수 있다.

## 상과 결정에 관한 약속

| 상태 | 계산에 쓰는 상 |
|---|---|
| `gas` 무대 | `g` |
| `solution` 무대 | 물은 `l`, 용질은 `aq` |
| `interface` 무대 | 원자 좌표 평균이 `surfaceY` 위면 `g`, 아래면 물 `l`·용질 `aq` |
| 전극·막·흙·뿌리·미토콘드리아·전지 | 용질 `aq`로 가정한다. 실제 비수용성 전해질이나 흡착 상태를 구별하지 않는다. |
| `lattice` 원자 | 원소 고체 `s`, 생성 엔탈피 0 |
| 물속 단독 중성 금속 원자 | 작은 금속 조각을 대표한다고 보고 `s`로 둔다. 기체 무대에서는 `g`이다. |
| `w.crystals`에 든 염 | 이온 종류를 대조해 염 `s`로 묶는다. |

금속 표면에 `land`로 닿은 이온은 `w.crystals`에 들어가지만 아직 `lattice`가 아니다. 이 이온은 `aq`로 유지한다. 전자를 내준 Zn도 `leave` 전까지 lattice 표시가 남는다. 환원과 이탈을 다른 단계로 쓰면 고체 0 약속에 따라 -211.58, -153.39로 나뉘며 합은 -364.97이다. 작업 중 compare 대본은 두 동작을 한 단계로 합쳤고 현재 표에는 -364.97이 한 번 나온다. 이는 실제 열이 발생하는 세부 시점을 측정했다는 뜻이 아니다.

결정은 이온 **묶음 수**를 화학식 단위에 들어가는 이온 수로 나눈다. CaCO3는 Ca2+ 하나와 CO32- 하나가 한 단위이며 원자 5개로 나누지 않는다. CaCl2는 이온 셋이 한 단위이다. 현재 엔진은 홀수 개 이온도 그린다. NaCl 5×3 격자에는 이온 15개가 있어 7.5단위로 센다. 표면에 남은 이온마다 같은 비중을 주는 화면용 약속이며, 비화학양론 결정의 정확한 에너지는 아니다. 이온 비율이 크게 어긋난 결정에도 이 약속이 적용되므로 정량 실험용으로 쓰지 않는다.

여러 음이온이 섞이거나 표면 이온이 H+를 받아 종류가 바뀌면 염을 임의로 추측하지 않는다. 고체 이온별 항을 남기고 값이 없으면 null로 돌려준다. 분자 결정은 분자별 `s`로 센다. 고체 값이 없으면 기체 결합 모형으로 대신하지 않는다.

둘레 물처럼 묶음 전체가 `crowd`인 화학종과 `gone` 표시가 있는 묶음은 제외한다. 일부 원자만 crowd인 반응 생성물은 묶음 전체를 센다. `attached`에 붙은 둘레 물은 용질에 공유 결합한 물이 아니므로 별도 열을 더하지 않는다. 수화열은 이미 aq 값에 들어 있으며 `solvate`로 다시 더하면 중복이다.

## 출처와 확인 범위

- [CODATA Key Values for Thermodynamics](https://codata.info/resources/databases/key1.html): 웹 원문에서 이온·물·기체·금속·AgCl·원자화 엔탈피를 직접 대조했다. 원문에서 대조한 항목만 `checked:true`이다. 수용액 이온은 **H+(aq)=0** 약속을 따른다.
- [NIST WebBook, bromomethane](https://webbook.nist.gov/cgi/cbook.cgi?ID=C74839&Mask=1): Ferguson/Okafo/Whittle(1973)의 CH3Br(g)=-34.3을 직접 대조했다. NIST에는 서로 다른 연구값도 있으며 여기서 고른 한 값이 유일한 권장값이라는 뜻은 아니다. aq 값을 확보한 것은 아니다.
- [NBS Tables, Wagman 등(1982)](https://srd.nist.gov/JPCRD/jpcrdS2Vol11.pdf): 표 링크는 찾았지만 웹 도구에서 PDF 용량 제한으로 본문을 열지 못했다. NBS로 표시한 값은 기억에서 옮겼으며 전부 `checked:false`이다.
- 그 밖의 NIST WebBook·CRC 표를 출처로 적은 값과 평균 결합 엔탈피는 기억에서 옮긴 잠정값이다. 원문 수치나 CRC 판을 확인했다고 주장하지 않는다. 이 값들은 교육용 정량 자료로 공개하기 전에 재대조해야 한다. 출처 문자열과 확인 여부를 각 값에 함께 저장했다.

H3O+(aq)는 별도 측정값 대신 H+(aq)+H2O(l)로 정의해 -285.83을 쓴다. `checked:true`는 구성 값의 대조를 뜻하며, 그 정의를 note에 명시했다. 이 약속으로 H3O+ + OH- → 2 H2O는 -55.815이다.

HCl(aq)는 무한 희석한 전해질을 나타내므로 H+(aq)+Cl-(aq)=-167.080이다. 따라서 HCl(aq)+H2O(l) → H3O+(aq)+Cl-(aq)는 **0**이다. 화면의 미해리 HCl 한 분자를 정확히 나타내는 값이 아니다. HCl(g)를 출발점으로 두면 -74.770이지만 현재 산 장면은 처음부터 solution 무대이므로 그 값을 적용하지 않는다. HBr(aq), HI(aq)에도 같은 전해질 약속을 쓴다. HBr 분자에 대한 실제 첨가 반응 경로와 혼동하지 않아야 한다.

## 어림 계산의 한계

중성 분자에서 `Σ(원소의 기체 원자화 엔탈피) - Σ(평균 결합 엔탈피)`로 기체 생성 엔탈피를 어림한다. 결합 차수 1·2·3을 구별한다. 결합 종류가 없거나 원자화 자료가 없거나 배위 결합이면 모름이다. 전하가 있는 화학종은 어림하지 않는다. Ad처럼 생략한 원자와 SEI로 표시한 구조도 이 모형으로 어림하지 않는다.

수용액 중성 분자에 표 값이 없으면 이 기체 어림값을 쓰되 `phase:aq, estimated:true`로 남긴다. 수화열·기화열·분자 사이 인력·고리 응력·공명·용액 농도·온도 효과는 계산하지 않는다. **aq 어림값은 수용액 표준 생성 엔탈피를 확보했다는 뜻이 아니다.** 알려진 기체 표 값을 aq 표 값으로 복사하지도 않는다.

CH3Br(aq) 값은 확보하지 못했다. 결합 모형으로 -32.456을 얻고, 표에 있는 CH3OH(aq)=-245.93, Br-(aq)=-121.41, OH-(aq)=-230.015를 사용하면 치환 반응은 -104.869이다. 대본 -75와 29.869 차이가 난다. 어림 결과를 맞추기 위해 aq 값을 역산해 표에 넣지 않았다. CH3Br 수화열 확보가 우선이다.

화학식만으로 이성질체와 전하 분포를 구별하지 못한다. `C2H6O`는 에탄올, `C3H8O`는 1-프로판올, `C6H12`는 시클로헥세인으로 등록했다. 같은 화학식을 가진 다른 구조에는 이 표를 그대로 적용하면 안 된다. 탄산 생성 중간체도 H2CO3와 같은 화학식이어서 같은 값으로 처리된다. 미지 중성 분자에서도 같은 화학식·상의 개수가 같으면 구조 변화는 상쇄된다.

## Claude가 효과 연결 전에 검토할 곳

1. **화면에 들어온 물질과 반응을 구별해야 한다.** `cell` 5단계는 염다리에서 K+·Cl- 두 쌍을 새로 만든다. 계산은 -838.44지만 이는 열이 아니라 계산 대상이 늘어난 결과이다. 이 단계에는 효과를 켜지 않는 편이 타당하다. 단순 입장·퇴장 명령도 같은 문제가 있다.
2. **둘레 물이 반응물이 되면 앞뒤 집계가 달라진다.** `condensation` 5단계 가수분해는 crowd 물을 소비한다. 반응 전 물은 제외되고 생성물은 포함되어 -233.824가 나온다. 이미 생긴 명시적 물을 소비하는 역반응이면 +52.006이 된다. 현재 API는 요청한 crowd 제외 규칙을 따랐고 자동 보정하지 않았다. 대본이나 호출 쪽에서 실제 반응물 집계를 정한 뒤 효과를 켜야 한다.
3. `cell` 반쪽 반응 값은 외부 전자·전기적 일을 포함한 실제 열 측정값이 아니다. 산화와 환원 합 -218.29는 생성 엔탈피 차이이며 전지 최대 전기 일인 ΔG와 다르다. 기존 -212를 이 표에 맞춰 수정하지 않았다.
4. `evaporation`, `boiling`, `ice`는 둘레 물만 바뀌어서 모두 0이다. 잠열이 없다는 뜻이 아니다. `heat`, `cool`, 막 수송, 흡착도 이 계산만으로 실제 열을 정할 수 없다.
5. 전지 예시는 비수용성 전해질과 흑연·금속 산화물 결합을 생략한다. aq·원소 고체 가정으로 나온 충방전 값은 실제 전지 열이 아니다. SEI도 생성물 조성이 없으므로 계산값 0을 검증된 반응열로 표시하지 않는다.
6. ADP·ATP는 생략 구조와 양성자화 상태를 실제 물질에 대응하기 전까지 모름으로 둔다. 대본 ±30은 생화학 ΔG를 연상시키는 값이며 ΔH 자료를 대신할 수 없다.
7. 표 값을 사용하더라도 `checked:false` 자료가 섞였는지 확인해야 한다. null을 0으로 간주하거나, 부분 terms의 합을 열로 표시하지 않는다. 결합 모형 결과는 약한 효과와 어림 표시가 적절하다.

## 효과 세기에 관한 제안

다음 수치는 화면 효과를 위한 **의견**이며 시각 검증 결과가 아니다. |dH| 5 미만은 거의 안 보이게 두고, 5~20은 약하게, 20 이상은 분명히 보이게 하는 시작값을 제안한다. 55.815인 중화와 65.720인 AgCl 한 쌍을 보통 세기로 삼으면 좋다. 200~250 부근에서 포화시키면 큰 단계 하나가 화면을 덮지 않는다. 세기는 그 범위 안에서 |dH|에 비례시킬 수 있다. 고리 반지름은 일정하게 두고 밝기·불투명도로 차이를 주는 편이 요청한 효과와 맞는다.

0인 단계가 대부분이므로 전체 중앙값을 기준 세기로 삼으면 안 된다. 아래에는 전체와 0이 아닌 단계, 원자 수가 맞는 단계의 분포를 나누었다. 원자 수가 맞아도 실제 반응열이 검증된 것은 아니다. 전자 이동 시점과 lattice 이탈 시점 배분은 별도 검토가 필요하다. ensemble 단계는 처음과 끝의 **순변화**만 계산하므로 도중에 일어난 정반응·역반응 횟수나 매 충돌의 효과 세기를 주지 않는다.

## 자동 집계 읽는 법

아래 표는 각 대본을 실제 `compile`로 컴파일하고 각 단계의 before/after에 `stepEnthalpy`를 호출한 결과이다. compare는 DOM 모듈을 import하지 않고 대본 상수와 SCENES 참조만 읽었다. 모든 단계는 1부터 센다. 대본 energy는 `to-from`을 표시하며 단위를 그대로 남긴다. 계산 척도와 energy의 반응식당 값은 항상 같은 단위가 아니므로 숫자 비교는 장면 계수를 함께 봐야 한다.

차이 표시는 숫자 차이가 10 이상이거나, 기준값의 10% 이상이면서 1을 넘으면 붙인다. 이 기준도 검토용 선택이다. `†`는 계산 대상 원소 개수가 앞뒤에서 달라진 단계이며 실제 반응열로 표시하지 않아야 한다. `‡`는 전지 생략 모형 단계이다. 어림 여부는 사용한 부분 항에 관한 표시이므로 null과 함께 ‘예’가 나올 수 있다.
