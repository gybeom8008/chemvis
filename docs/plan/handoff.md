# 다음 주부터 Opus에게 맡기는 방법

상태: 안 · 2026-11-10 · [기획안 개요](README.md)

## 1. 생각

모델 사이의 차이는 "무엇을 어떻게 할지 정해져 있지 않은 일"에서 크게 드러난다. 그래서 이번 주에 정해져 있지 않은 부분을 없앤다.

- 판단이 필요한 일(구조, 규칙, 본보기)은 이번 주에 끝낸다.
- 다음 주부터의 일은 "본보기를 따라 하나 더 만드는 일"이 되게 한다.
- 규칙은 글로만 두지 않고 검사로 만든다. 글로 쓴 규칙은 잊힐 수 있지만, 검사에서 실패한 작업은 끝난 것으로 칠 수 없다.

## 2. 장치 여섯 가지

| 장치 | 위치 | 하는 일 |
|---|---|---|
| CLAUDE.md | 저장소 맨 위 | Claude Code가 세션을 시작할 때마다 읽는 파일이다. 작업 순서, 꼭 읽을 문서, 하면 안 되는 일을 한 화면 분량으로 적는다 |
| 본보기 | 수업, 반응 규칙, 예시마다 하나 | 종류마다 완성된 것을 하나씩 둔다. 새 것은 본보기를 복사해서 시작한다 |
| 검사 | `npm run check` | 수업 형식, 대본 컴파일, 글자 수, 화면 규칙, 실험실이 모르는 것을 모른다고 답하는지 |
| 화면 사진 | `npm run shots` | 모든 화면을 폰과 PC 크기로 찍어 기준 사진 옆에 나란히 둔다. 화면을 고친 작업은 이 사진을 직접 보고 나서 끝낸다 |
| 작업 절차 | `.claude/skills/` | '수업 추가', '반응 규칙 추가', '화면 고치기'의 순서를 적은 파일. Claude Code가 그 작업을 할 때 불러서 따른다 |
| 작업 목록 | `docs/backlog.md` | 작은 작업으로 나눈 목록. 작업마다 고칠 파일과 끝났다는 기준을 적는다 |

## 3. 일 나누기

| 분야 | 이번 주 (Fable) | 다음 주부터 (Opus) |
|---|---|---|
| 화면 | 뼈대, 부품, 화면 검사, 기준 사진 | 규칙 안에서 문구와 아이콘 다듬기 |
| 수업 | 재생기, 수업 형식, 본보기 3편, 기존 25장 옮기기 | '새 장면' 수업 18편을 본보기대로 쓰기 |
| 엔진 | 원자 무대, 주기율표, 부분 전하 표시 | 등록 분자 추가 |
| 실험실 | 재료 넣기, 규칙 엔진, 규칙 5종, 표의 형식 | 표에 줄 더하기, 2차 규칙을 본보기대로 더하기 |
| AI 장면 | 서랍 정리, 내 장면, 용어 연결 | 예시 장면 추가 |
| 문서 | CLAUDE.md, 작업 절차, 작업 목록 | 작업 목록 갱신 |

## 4. Opus에게 주지 않는 일

- 새 화면 영역이나 새 부품 만들기
- 애니메이션 방식 바꾸기
- 엔진 구조 바꾸기
- 교육 과정의 단원 순서 바꾸기

작업 중에 이런 일이 필요해지면, 작업 목록에 '설계 필요'라고 적고 그 작업을 멈추라고 CLAUDE.md에 적어 둔다. 다음에 Fable을 쓰실 때 그 항목부터 처리한다.

## 5. 예행연습

일요일에 Opus에게 수업 한 편과 규칙 한 줄을 실제로 시켜 본다. Claude Code는 하위 작업을 다른 모델에게 시킬 수 있으므로 이번 주 안에 할 수 있다.

- Opus는 저장소를 처음 보는 상태로 시작한다.
- 결과가 본보기와 어긋난 곳마다, 그렇게 만든 문서나 검사를 고친다. Opus의 결과물을 직접 고쳐서 끝내지 않는다.
- Opus가 추가 설명 없이 검사를 통과하는 결과를 내면 준비가 끝난 것이다.

## 6. 다음 주부터 하실 말

작업 목록과 절차가 있으므로 짧게 말씀하시면 된다.

| 하시는 말 | Opus가 하는 일 |
|---|---|
| "다음 작업 해" | 작업 목록의 맨 위 항목을 절차대로 하고, 검사와 화면 사진을 확인한 뒤 배포한다 |
| "수업 6-3 만들어" | '수업 추가' 절차대로 본보기를 복사해서 쓴다 |
| "실험실에 마그네슘 넣어" | 표에 줄을 더하고 그 줄의 검사를 더한다 |
| "이 화면 이상해" | '화면 고치기' 절차: 어느 규칙(R1~R18)에 어긋나는지 찾고, 고친 뒤 화면 사진으로 확인한다 |
