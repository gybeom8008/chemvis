# 인계서: 클라우드 세션에서 로컬 세션으로

작성: 2026-11-10 · 고침: 2026-11-11(7.1, 8절) · [기획안 개요](README.md)

이 문서는 클라우드 세션에서 하던 일을 윤범님 컴퓨터의 로컬 세션이 이어서 하도록 쓴 것이다. 클라우드 세션의 대화 기록은 로컬로 옮겨지지 않는다. 이어서 일하는 데 필요한 것은 이 문서, 저장소, 그리고 Notion 'AI 기억'의 chem-viz-app 페이지에 있다.

## 1. 지금 상태

| 무엇 | 어디 |
|---|---|
| 저장소 | `gybeom8008/chemvis` (공개, 브랜치는 `main` 하나) |
| 앱 | https://gybeom8008.github.io/chemvis/ |
| 비교 화면 (오른쪽이 검토할 방식, 왼쪽은 견줄 방식) | https://gybeom8008.github.io/chemvis/concept/ |
| 앱 전체를 새 방식으로 보기 | 앱 주소 뒤에 `?style=pairs` |

- 앱의 기본 방식은 아직 지금 방식(`lines`: 결합은 선, 전자의 이동은 굽은 화살표)이다.
- 새 방식(`pairs`: 전자쌍 주머니)은 비교 화면의 12개 장면에서 완성도를 높이는 중이다.
- 새 방식에 대한 윤범님의 평가: "전자의 이동과 결합의 이동이 직관적으로 보여." 다만 **확정한다는 말은 아직 없었다.** 다른 반응 표현도 더 고친 뒤에 확정한다.
- 탭 셋(배우기 / 실험실 / AI 장면), 수업, 실험실 구현은 모두 보류다. 기획서만 있다.

## 2. 이 프로젝트에서 가장 중요한 것

**화학 반응에서 실제로 일어나는 일(전자의 이동, 결합의 변화)을 설명을 읽지 않고도 보자마자 알 수 있게 그리는 것.** 윤범님의 말로는 "이 웹앱의 알파이자 오메가"다.

윤범님이 "디자인이 비직관적이다"라고 하면 탭, 무대, 버튼 같은 주변 화면이 아니라 **반응을 그린 장면 자체**를 먼저 의심한다. 클라우드 세션은 이것을 주변 화면 문제로 잘못 읽고 탭과 무대를 다시 만들었다가 크게 혼났다. 캡처한 화면을 볼 때도 주변이 아니라 그 안의 화학이 읽히는지를 본다.

## 3. 윤범님이 정한 것

1. 탭 이름은 배우기 / 실험실 / AI 장면.
2. 배우는 사람을 따로 정하지 않는다. 계산 문제가 있는지 없는지는 중요하지 않다. 직관적으로 시각화해서 마찰 없이 익히게 하는 것이 중요하다.
3. PC 화면을 먼저 제대로 만든다. 폰 화면은 그 뒤에 PC 화면을 고쳐서 만든다.
4. 반응 표현에 집중한다. **하나를 고칠 때마다 앱 전체를 새 방식으로 바꾸지 않는다(사용량 절약).** 고치는 일은 비교 화면에서만 한다.
5. 반응 표현을 확정하면 그때 앱 전체에 적용한다. 나머지(탭, 수업, 실험실)는 기획서가 있으면 다른 모델도 할 수 있는 일로 본다.
6. 실험실의 기획과 설계는 Astra에게 맡겼다.
7. 다음 주부터는 Opus로 작업한다. 그래서 기획서와 검사 장치를 남긴다([handoff.md](handoff.md)).

## 6. 새 방식에서 지켜야 할 것

원리는 [depiction.md](depiction.md)에 있다. 요약하면 이렇다.

- 전자쌍 하나하나가 눈에 보이는 주머니다. 원자 하나에 있으면 비공유 전자쌍, 두 원자 사이에 있으면 결합이다. 결합선과 굽은 화살표는 없다.
- 반응은 주머니가 한 원자에서 떨어지거나 다른 원자를 새로 감싸는 움직임이다. 새로 감싸는 쪽이 먼저 움직이고 떨어지는 쪽이 뒤따른다.
- 홑전자는 반쪽 주머니다. 원자에서 원자로 가는 전자는 하나씩 날아가고, 전하는 전자 하나마다 바뀐다.
- 결정 안의 이온, 분자 여러 개가 부딪치는 장면, 배경의 물에는 전자를 그리지 않는다.

**흔들림 규칙.** 분자는 열운동으로 계속 조금씩 흔들린다. 전자쌍의 방향이나 전하 표시의 방향처럼 여럿 가운데 하나를 고르는 일을 그 순간의 좌표로 하면, 비슷한 후보 사이에서 프레임마다 선택이 바뀌어 표시가 깜빡거린다. 그래서 이런 선택은 **저장된 좌표(World)로 한 번만 정하고, 그 뒤에는 분자가 회전한 만큼만 따라 회전시킨다.** `pairs.ts`의 `domainsOf`, `turnOf`, `stableFreeAngle`, `stableDomains`, `blendDomains`가 이 일을 한다. 새 표시를 더할 때도 이 함수들을 쓴다.

**화면을 고친 뒤의 확인 순서.**

1. `npm run shot`으로 처음·중간·끝을 캡처해서 직접 본다. 화학이 맞는지, 보자마자 읽히는지.
2. `npm run flicker`로 실제 속도에서 튀는 표시가 없는지 잰다. 캡처는 정지 화면이라 깜빡임이 보이지 않는다. 클라우드 세션은 캡처만 보고 넘어갔다가 윤범님이 깜빡임을 먼저 발견했다.
3. `npm test`, 그리고 빌드 후 `npm run e2e`.

## 7. 남은 일

### 7.1 반응 표현에서 아직 거친 부분

| | 무엇 | 어디서 보이나 |
|---|---|---|
| 1 | **원자와 전하를 그리는 방법을 다시 검토하는 중이다.** 윤범님이 원소 표기와 이온 표기가 직관적이지 않다고 했다(2026-11-11). 검토안은 비교 화면 오른쪽에 있다([depiction.md](depiction.md) 2.2). 윤범님의 평가를 기다린다 | 비교 화면 전체 |
| 2 | 반응하는 큰 분자(ADP, 인산)는 바뀌지 않는 원자의 전자까지 모두 그려서 점이 많다 | 앱에 `?style=pairs`, 예시 '미토콘드리아' 4–6단계 |
| 3 | 축합의 마지막에 이어진 분자 전체가 크게 돈다 | 비교 화면 '축합' |
| 4 | 예시 가운데 리튬 이온 전지와 종유석은 새 방식에서 아직 눈으로 보지 않았다. 석회 동굴, 미토콘드리아, 뿌리털은 2026-11-11에 봤다(`node tools/shot-app.cjs`) | 앱에 `?style=pairs` |
| 5 | 지금 방식에서만: 라디칼 장면 둘째 단계에서 Cl의 점이 한 번 튄다. 지금 방식은 없앨 예정이라 남겼다 | `SIDES=old npm run flicker` |

2026-11-11에 만든 것: 침전의 각진 판과 금속 조각(비교 화면 '침전', '금속 조각'. 엔진 명령 `metal`, `land`, `join`, `leave`, `precipitate using`). 금속 장면에서 둘째 전자가 아연 원자 위를 지나가는 것은 남아 있다.

2026-11-11에 고친 것: 축합에서 두 전자쌍이 엇갈리던 것(다가가는 분자가 다음 단계의 축합을 보고, 떨어져 나갈 H가 -OH 옆에 오는 틈으로 들어간다), 양성자가 이동할 때 전하 표시가 전자쌍 위를 지나가던 것(옛 표시는 제자리에서 흐려지고 새 표시는 제자리에서 나타난다), 반응에 끼지 않는 이온의 점(황산 이온처럼 장면 내내 아무 변화가 없는 분자와 이온은 전자를 그리지 않는다. `pairs.ts`의 `bystanders`), 용해의 지그재그 흔적(떠도는 경로의 모서리를 둥글게 했다).

## 8. Astra와 함께 일하기

### 8.1 지금까지

- 클라우드 세션은 윤범님의 ChatGPT 계정을 쓸 수 없어서 의뢰서([lab-brief.md](lab-brief.md))만 썼고, 윤범님이 Astra에게 전달했다.
- Astra의 결과가 [lab-astra.md](lab-astra.md)다. 기준 커밋은 `c814963`이다.
- 클라우드 세션이 그 문서에서 확인한 사실은 다음과 같다.
  - 대본 예시 일곱 개(A01, A03, A04, P01, D01, R01, R02)는 지금 엔진에서 오류 없이 컴파일되고, 끝 상태가 문서의 생성물과 같다.
  - logK, Q/Ksp, E°cell, E 범위를 다시 계산했고 전부 일치했다.
  - 엔진에 대한 주장 세 가지(컴파일은 늘 새 장면에서 시작한다, `precipitate`는 화학식이 같은 이온 가운데 앞의 것부터 고른다, 아세트산의 OH는 O2와 H4다)는 맞다.
- [lab-review.md](lab-review.md)의 4절 이후는 클라우드 세션의 **의견**이다. 윤범님이 정한 것이 아니고, 윤범님은 이 검토를 더 하지 말라고 했다. 로컬에서 Astra와 직접 이야기해서 정한다.

### 8.2 Astra가 본 뒤로 바뀐 것

Astra는 `c814963`을 읽었다. 그 뒤에 바뀐 것을 Astra에게 알려야 한다.

| 바뀐 것 | 내용 |
|---|---|
| 알짜 반응의 표현 | 축합과 가수분해도 전자쌍이 주인을 바꾸는 모습으로 그린다(`StepAnim.shifts`) |
| 다가가는 까닭 | `approach`가 부분 전하 표시와 점선으로 서로 당기는 것을 보여 준다(`StepAnim.pulls`). 비어 있는 쪽이 없는 원자에는 가장 넓은 틈으로 다가간다 |
| 전극의 전자 | `oxidize`/`reduce`의 전자가 전극의 정해진 위치까지 도중에 사라지지 않고 이어진다(`ArrowAnim.free`, `plateSlot`) |
| 단순하게 그리는 장면 | 결정 안의 이온, 분자 여러 개의 장면, 배경의 물에는 전자를 그리지 않는다 |
| 흔들림 규칙 | 6절. 두 방식 모두에 적용했다 |
| 비교 화면 | 장면 12개. `window.cmp.script(대본)`으로 아무 대본이나 볼 수 있다 |
| 도구 | `npm run flicker`, `npm run shot` |

### 8.3 Astra와 정한 것

## 9. 윤범님과 일하는 방식

말투와 금지어 같은 개인 설정은 계정 설정에 있어서 로컬 세션도 그대로 읽는다. 이 프로젝트에서 따로 지킬 것만 적는다.

- **확인을 구하지 않고 끝까지 한다.** 윤범님의 말: "내 확인 받을 생각 말고 네가 해야 할 거 알아서 다 해."
- **허락 창이 뜨는 일을 피한다.** 윤범님은 허락 창을 매우 싫어한다. `.claude/settings.json`에서 Bash, Notion, 웹 검색을 미리 허락해 두었다.
- **사용량을 아낀다.** 3절의 4번.
- **확인하지 않은 것을 확인했다고 말하지 않는다.** 6절의 확인 순서를 지킨다.
- 금지어 목록은 채팅뿐 아니라 **앱의 화면 문구와 문서에도** 적용한다. 예: 조절 막대의 이름은 "직접 움직여 보기", 버튼은 "실행 취소", "접기".
- git: `main`에만 push한다. PR은 요청이 있을 때만 만든다. 강제 push는 하지 않는다. 커밋 메시지에 모델 이름을 쓰지 않는다(맺음 줄 제외).
- 기억은 Notion 'AI 기억'의 chem-viz-app 페이지(`40fdbcea-2e7d-81e7-83a4-f2d51de66e19`)에 적는다. 맨 끝에 이어서 적는다.
- 외부 서비스에 보내는 요청에 윤범님의 이름, 이메일 같은 개인 정보를 넣지 않는다.
