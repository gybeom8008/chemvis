### 1.1 화면

- 머리줄에 탭 셋(학습 / 시연 / 실험실)과 도구 넷(예시, 대본, 보기 설정, 링크)이 있다.
- **학습과 시연은 한 화면, 한 무대다**(윤범님, 11-17). 학습은 시연 화면에 수업 목록만 더한 것이다(`index.html`의 `#work`, `src/main.ts`의 `showPlace`). 학습으로 가면 목록이 왼쪽에서 0.2초에 미끄러져 들어온다. 두 화면은 각자 장면과 단계를 기억해서, 탭을 오가도 보던 것이 남는다.
- 위에서 아래로 제목(명조), 무대, 그리고 자막과 조작 줄로 이루어진 상자 하나가 있다. 셋은 왼쪽 끝과 오른쪽 끝이 같다. 범례는 무대 폭이 760px 이상이면 이 단 오른쪽에 늘 보이고, 좁으면 무대 왼쪽 아래의 버튼 안에 있다.
- 자막 상자는 그 장면에서 가장 긴 자막에 맞춘 높이로 고정되어, 단계마다 무대 크기가 바뀌지 않는다.
- **시연은 빈 무대로 시작하지 않는다**(11-19). 주소에 장면이 없으면 첫 예시(석회 동굴)를 재생한다. 빈 무대는 새 대본을 쓸 때(`#/edit`)와 링크의 대본을 읽지 못했을 때만 나온다.
- 주소: 학습 `#/t/수업 id`, 실험실 `#/lab`, 예시 `#/x/예시 id`, AI가 쓴 장면 `#z=…`(대본을 압축한 것), 새 대본 `#/edit`. 그 밖의 주소는 모두 시연이다.
- 보기 설정: 전하, 분자 사이 인력, 산화수, 원자 일련번호, 반응열 효과, 전하 색(빨강이 + / 빨강이 −), 속도, 이어서 재생. 반응열과 전하 색은 다음 방문에도 유지된다(주소의 `?heat=off`, `?palette=red-negative`도 된다).
- 화면에 보이는 화학식은 조판한다(`src/chem/format.ts`: `H3O+` → H₃O⁺, `CO32-` → CO₃²⁻). 대본과 엔진은 평범한 표기를 그대로 쓴다.
- **자막 속 용어**(공유 결합, 산화, 중화 등 50개쯤)에는 점선 밑줄이 있고, 누르면 뜻과 그 용어를 배우는 수업이 카드로 나온다(11-19, `src/tutorial/glossary.ts`). 기획서가 "가장 중요하다"고 적은 연결이다: AI가 쓴 장면을 보다가 용어를 몰라도 바로 그 수업으로 간다. 새 수업을 더하면 그 수업이 가르치는 용어도 용어집에 더한다.
- 폭 820px 이하에서는 수업 목록과 대본이 화면 위에 겹쳐 나온다. 821–1120px에서 학습 중에 대본을 펼치면 목록이 접힌다. 폰에서는 무대가 화면 높이의 절반쯤이고, 누르는 곳은 모두 44px 이상이다.
- **실험실은 탭과 빈 화면만 있다.** 윤범님이 만들어 보고 싶은 것이 있다고 했으니 그 말이 있기 전에는 채우지 않는다. 예전 작업은 [archive/lab](../../archive/lab/README.md)에 있다.

### 1.2 반응 표현

## 2. 이 프로젝트에서 가장 중요한 것

**화학 반응에서 실제로 일어나는 일(전자의 이동, 결합의 변화)을 설명을 읽지 않고도 보자마자 알 수 있게 그리는 것.** 윤범님의 말로는 "이 웹앱의 알파이자 오메가"다.

윤범님이 "디자인이 비직관적이다"라고 하면 탭, 무대, 버튼 같은 주변 화면이 아니라 **반응을 그린 장면 자체**를 먼저 의심한다. 예전 세션은 이 말을 주변 화면 문제로 잘못 읽고 탭과 무대를 다시 만들었다가 크게 혼났다. 캡처한 화면을 볼 때도 주변이 아니라 그 안의 화학이 읽히는지를 본다.

## 4. 무대 바깥의 디자인 언어 (11-19)

자세한 규칙은 [ui.md](ui.md) 1절에 있다. 요점만 적는다.

- 무대 안은 사용자가 바꿀 수 없는 법칙대로 움직이고, 바깥은 사용자의 손에 바로 따른다. 이 대비가 "반응은 사용자가 일으키는 것이 아니라 법칙에 따라 일어난다"는 것을 보여 준다.
- 나누는 기준은 원인이다. 사용자의 입력에 대한 반응은 바로 따르고, 장면의 상태를 알리는 것(자막, 진행 줄의 단계)은 장면의 사건에 맞춰 바뀐다.
- 원, 빛 번짐, 색은 무대 전용이다. 바깥은 종이와 먹, 곧은 선, 둥글기 두 가지(4px, 8px)만 쓴다.

## 5. 시작하기

Node 22가 필요하다. 처음 한 번 `npm ci`를 실행한다.

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버. 앱은 `/`, 비교 화면은 `/concept/` |
| `npm run build` | 형식 검사 후 빌드 |
| `npm test` | 단위 검사 |
| `npm run e2e` | 화면 검사(Firefox와 Chromium). 빌드한 뒤에 실행한다 |
| `npx vite preview --port 4173 --strictPort` | 빌드한 것을 4173번에서 보여 준다. 아래 세 도구는 이 서버가 켜져 있어야 한다 |
| `npm run flicker` | 비교 화면을 실제 속도로 재생하면서 전자, 주머니, 전하 표시가 한 프레임 사이에 다른 쪽으로 튀는지 잰다(`SIDES=old,new`로 양쪽) |
| `npm run cross` | 전자쌍이 서로 가로지르거나 늘어나는지 잰다 |
| `npm run shot -- out.png acid 1:0.1,1:0.5,1:1` | 장면의 원하는 순간들을 한 장으로 캡처한다. 장면 이름 대신 대본 파일을 줄 수 있다 |

**클라우드 세션에서.** Chromium만 있다. 화면 검사는 `npx playwright test --project=chromium`으로 실행하고, Firefox 검사는 push한 뒤 CI의 결과로 확인한다. 미리보기 서버는 뒤에서 실행해 두고, 꺼지면 다시 켠다.

**push하기 전에** `npm test`(단위 검사 전체)와 빌드 뒤의 화면 검사를 반드시 실행한다. 단위 검사의 가짜 무대에는 DOM 함수가 없으므로, 그리기 코드에서 DOM을 쓸 때는 없는 경우를 막아 둔다(2026-11-19에 이것을 빠뜨려 배포가 한 번 멈췄다).

## 7. 그림을 고칠 때 지킬 것

원리는 [depiction.md](depiction.md)에 있다. 요약하면 이렇다.

- 전자쌍 하나하나가 눈에 보이는 주머니다. 원자 하나에 있으면 비공유 전자쌍, 두 원자 사이에 있으면 결합이다. 결합선과 굽은 화살표는 없다.
- 반응은 주머니가 한 원자에서 떨어지거나 다른 원자를 새로 감싸는 움직임이다. 결합이 바뀌는 단계는 모두 한 시계를 쓴다: 버티다가 한순간에 전자쌍, 원자, 전하, 열이 함께 바뀐다.
- 홑전자는 반쪽 주머니다. 원자에서 원자로 가는 전자는 하나씩 날아가고, 전하는 전자 하나마다 바뀐다.
- 결정 안의 이온, 분자 여러 개가 부딪치는 장면, 배경의 물에는 전자를 그리지 않는다.

**흔들림 규칙.** 분자는 열운동으로 계속 조금씩 흔들린다. 전자쌍의 방향이나 전하 표시의 방향처럼 여럿 가운데 하나를 고르는 일을 그 순간의 좌표로 하면, 비슷한 후보 사이에서 프레임마다 선택이 바뀌어 표시가 깜빡거린다. 그래서 이런 선택은 **저장된 좌표(World)로 한 번만 정하고, 그 뒤에는 분자가 회전한 만큼만 따라 회전시킨다.** `pairs.ts`의 `domainsOf`, `turnOf`, `stableFreeAngle`, `stableDomains`, `blendDomains`가 이 일을 한다. 새 표시를 더할 때도 이 함수들을 쓴다.

**고친 뒤의 확인 순서.**

1. `npm test`, `npm run flicker`, `npm run cross`로 수치를 먼저 본다. 캡처는 정지 화면이라 깜빡임이 보이지 않는다. 예전 세션은 캡처만 보고 넘어갔다가 윤범님이 깜빡임을 먼저 발견했다.
2. 코드로 알 수 없는 것만 `npm run shot`으로 캡처해서 본다. 화학이 맞는지, 보자마자 읽히는지.
3. 빌드 후 화면 검사.

## 9. 윤범님과 일하는 방식

말투와 금지어 같은 개인 설정은 계정 설정에 있어서 어느 세션이든 그대로 읽는다. 이 프로젝트에서 따로 지킬 것만 적는다.

- **확인을 구하지 않고 끝까지 한다.** 윤범님의 말: "내 확인 받을 생각 말고 네가 해야 할 거 알아서 다 해." 질문에는 답만 하고, 승인 절차를 더하지 않는다.
- **허락 창이 뜨는 일을 피한다.**
- **쉬운 말로 한다.** 윤범님은 개발 용어(브랜치, `main` 같은 것)를 모를 수 있다. 용어는 풀어서 쓰고, 참고 자료는 이름만 말하지 않고 무엇인지와 링크를 함께 준다(11-19).
- **사용량을 아낀다.** 3절의 11-10 셋째 줄.
- **확인하지 않은 것을 확인했다고 말하지 않는다.** 7절의 확인 순서를 지킨다.
- 금지어 목록은 채팅뿐 아니라 **앱의 화면 문구와 문서에도** 적용한다. 예: 조절 막대의 이름은 "직접 움직여 보기", 버튼은 "실행 취소", "접기".
- git: `main`에만 push한다. PR은 요청이 있을 때만 만든다. 강제 push는 하지 않는다. 커밋 메시지에 모델 이름을 쓰지 않는다(맺음 줄 제외).
- 외부 서비스에 보내는 요청에 윤범님의 이름, 이메일 같은 개인 정보를 넣지 않는다.
