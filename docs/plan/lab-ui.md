## 2. PC 배치

### 2.1 영역과 크기

기준 화면은 1440×900 CSS px다. PC 분기점은 폭 900px이고, 900×640에서도 같은 영역 순서를 유지한다. 바깥 여백을 더해 무대를 줄이지 않는다. 화면 전체는 고정하고 서랍 내용만 세로로 스크롤한다.

| 영역 | 크기 | 들어가는 것 |
|---|---|---|
| 왼쪽 탭 | 폭 72px, 화면 전체 높이 | 배우기 / 실험실 / AI 장면. 현재 탭만 먹색으로 표시한다 |
| 오른쪽 서랍 | 폭 `clamp(280px, 22vw, 320px)`, 전체 높이 | 재료·결과·기록 중 한 내용. 별도 서랍을 겹쳐 열지 않는다 |
| 가운데 위 줄 | 높이 56px, 남은 폭 | `수용액 반응` / `분자 조립` 선택, 조건 한 줄, 보기 설정. 폭 900px에서도 한 행이다. 모드 버튼 둘을 붙인 영역 208×44px, 조건 폭 156px, 보기 설정 44×44px, 세 영역 사이 간격 8px씩, 좌우 안쪽 여백 12px로 최소 폭 448px 안에 배치한다 |
| 무대 | 가운데 남은 폭, 높이 `화면 높이 − 206px` | 입자, 접촉 후보 고리, 범례. 1440×900에서 약 1051×694px, 900×640에서 548×434px다 |
| 설명 줄 | 높이 94px | 결과 제목 또는 지금 조작 안내 한 가지, `자세히` 44×44px. 제목은 최대 세 줄이고 자막이 바뀌어도 높이는 같다 |
| 조작 줄 | 높이 56px | 왼쪽 `실행 취소`, `다시 실행`, 오른쪽 주 버튼 하나. 버튼은 최대 셋이다 |

무대 안내 `입자 몇 개로 반응 한 번을 봐요.`는 무대 상단 경계에 예약한 24px 안내 줄에 둔다. 입자 위로 떠다니는 카드가 아니다. 조립에서는 같은 자리에 `원자 모형을 연결해 분자 구조를 조립해요.`를 둔다. 이는 합의문의 필수 안내를 넣기 위한 R4의 좁은 적용 판단이다. 안내 줄을 빼고도 900×640의 입자 공간은 410px로 화면 높이의 55%보다 크다. 결과 카드·재료 목록·대기 선반은 무대 위에 올리지 않는다.

오른쪽 서랍은 머리 48px(`재료` / `결과` / `기록`), 내용 `남은 높이`, 바닥 48px로 나눈다. 재료 화면의 검색은 44px, 분류 선택은 44px, 목록 한 줄은 최소 56px다. 긴 문구는 줄바꿈하고 줄 높이를 늘린다. 바닥의 `비우기`는 재료 화면에서만 보인다. 결과의 긴 설명은 서랍 안에서 스크롤하므로 무대가 줄지 않는다.

모든 조작 영역은 최소 44×44px다. 글자 크기는 12·14·16·18px, 굵기는 보통·굵게만 쓴다. 조건·보조 표시는 12px, 서랍 본문 14px, 결과 제목 16px, 화면 제목 18px다. 화면 뼈대와 후보 고리는 무채색이다. 성공·부정·모름을 빨강·초록으로 나누지 않는다.

### 2.2 두 모드

첫 진입은 `수용액 반응`이며 빈 무대와 재료 서랍을 함께 보여 준다. 자동으로 반응하거나 메뉴만 보여 주지 않는다. 조건은 `25 °C의 묽은 물속`으로 고정하고 누르는 곳처럼 꾸미지 않는다. 온도·묽기·가열·빛 선택은 없다.

`분자 조립`을 고르면 물속 배경과 조건 표시가 없어지고 평평한 작업판이 나온다. 두 모드는 각각 World/조립판, 선반, 기록, 마지막 결과, 검색어를 메모리에 보관한다. 전환은 내용을 비우지 않으며 화학 사건이나 실행 취소 항목으로 세지 않는다. 탭을 오가도 같은 세션 동안 보존한다. 새로고침 뒤 복원과 외부 장면 가져오기는 단계 1 필수 기능이 아니다.

끌기·후보 선택·재료 부족 대기 중 모드를 바꾸면 미확정 접촉을 취소하고 시작 위치를 복원한 뒤 전환한다. 재생·사전 검사 중에는 모드와 앱 탭 전환을 잠근다. 먼저 실행 취소 또는 재생 종료를 거쳐야 한다. 물·암모니아 모형을 `반응 재료로 넣기`로 보내는 경우만 목적 모드에 새 인스턴스를 추가하고 그 모드로 이동한다. 조립판 원본은 보존한다.

## 3. 재료 서랍

### 3.1 단계 1 재료 15종

`재료` 내용은 `시작 묶음` 네 줄, 검색, `전체` / `분자` / `이온` / `고체` 분류, 재료 목록, `대기 선반` 순이다. 전체 목록은 아래 순서를 유지하고 분류·검색은 이 순서에서 걸러 낸다. 원래 설계의 자유 원소 탭은 수용액 모드에 만들지 않는다. 원자 모형은 조립 모드에서만 넣는다.

표시 이름 옆에 화학식을 함께 쓴다. 재료 줄 전체가 넣기 동작이며 별도 `넣기` 버튼을 같은 줄에 중복하지 않는다. 작은 구조 그림은 클릭 영역 안에 포함한다. 이름만으로 물속 이온과 고체를 섞지 않는다.

| 순서 | 내부 ID | 표시 이름 | 화학식·분류 | 한 번 고를 때 |
|---:|---|---|---|---|
| 1 | water | 물 | H₂O · 분자 | 선택 가능한 물 1개 |
| 2 | hydronium | 하이드로늄 이온 | H₃O⁺ · 이온 | 이온 1개 |
| 3 | hydroxide | 수산화 이온 | OH⁻ · 이온 | 이온 1개 |
| 4 | ammonia | 암모니아 | NH₃ · 분자 | 분자 1개 |
| 5 | ammonium | 암모늄 이온 | NH₄⁺ · 이온 | 이온 1개 |
| 6 | silver-ion | 은 이온 | Ag⁺ · 이온 | 이온 1개 |
| 7 | chloride | 염화 이온 | Cl⁻ · 이온 | 이온 1개 |
| 8 | silver-chloride | 염화 은 고체 | AgCl · 고체 | 조성 한 쌍, 이온 2개인 판 1개 |
| 9 | sodium-ion | 나트륨 이온 | Na⁺ · 이온 | 이온 1개 |
| 10 | sodium-chloride | 소금 결정 | NaCl · 고체 | Na⁺ 6개와 Cl⁻ 6개인 판 1개 |
| 11 | zinc-metal | 아연 조각 | Zn · 고체 | 추적 원자 6개를 2×3으로 놓은 조각 1개 |

재료 줄을 누르면 다른 입자와 접촉하지 않는 빈 자리에 놓고 그 입자를 선택한다. 공간을 만들 수 없으면 무대를 재배치하거나 반응을 일으키지 않고 추가를 보류한다. 추가 위치 안내는 설명 줄에 둔다. 서랍에서 무대로 끌어 넣는 경우도 먼저 추가만 확정한다. 그 동작으로 반응까지 실행하지 않는다.

한도는 활성 무대의 종류별 6단위, 전체 24단위다. 물·분자·자유 이온은 하나당 1, 이온 결정은 조성 한 쌍당 1, 금속은 추적 원자 하나당 1이다. 따라서 금속 조각 하나는 6단위, 소금 조각 하나도 6단위다. 반응 뒤 자유 이온과 고체 소속은 현재 상태로 다시 센다. 배경 물은 세지 않는다. 한도는 추가·선반 복귀 전에 완성될 상태까지 검사하고 반쪽 추가를 하지 않는다. 문구는 `무대에는 입자 24개까지 놓을 수 있어요.` 또는 `같은 재료는 6개까지 놓을 수 있어요.`다. 고체 줄 보조 표시로 `한 조각에 6개`를 함께 보여 준다. 수량 한도는 화학 판정이 아니다. 반응 생성물 때문에 한도를 넘는 경우에는 검증한 생성물을 모두 보존하고 다음 추가만 막는다. 생성물을 버리거나 한도를 반응 부정 사유로 쓰지 않는다.

### 3.2 시작 묶음 넷

네 줄은 아래 순서와 이름으로 고정한다. 괄호 내용은 줄 아래의 재료 요약이다. 묶음을 고르면 활성 재료와 선반을 그 묶음으로 교체한다. 이 동작 전체가 실행 취소 한 항목이다. 줄 아래 공통 안내는 `지금 재료를 바꿔 놓아요. 실행 취소할 수 있어요.`다. 확인창은 열지 않는다. 배경 물은 각 묶음에서 따로 제공하는 용매 그림이다.

| 순서·표시 이름 | 활성 무대 | 대기 선반 | 첫 조작 안내 |
|---|---|---|---|
| 1. 물 만들기 | H₃O⁺ 1개, OH⁻ 1개 | 없음 | H₃O⁺를 OH⁻ 가까이 가져가요. |
| 2. H 주고받기 | H₃O⁺ 1개, NH₃ 1개, OH⁻ 1개 | 없음 | H₃O⁺를 NH₃ 가까이 가져가요. |
| 3. 고체가 생기기 | Ag⁺ 3개, Cl⁻ 3개 | 없음 | Ag⁺를 Cl⁻ 가까이 가져가요. |
| 4. 금속 바꾸기 | Zn 조각 1개, Cu²⁺ 1개 | 순수 Cu 조각 1개, Ag⁺ 2개 | Cu²⁺를 아연 조각 가까이 가져가요. |

물 만들기는 왼쪽/오른쪽에 한 재료씩 놓는다. H 주고받기는 H₃O⁺·NH₃를 가운데 양옆, OH⁻를 떨어진 아래쪽에 둔다. 고체가 생기기는 Ag⁺ 열과 Cl⁻ 열을 나란히 둔다. 금속 바꾸기는 아연 조각을 왼쪽, 구리 이온을 오른쪽에 둔다. 시작 배치에서 접촉 미리보기를 켜지 않는다. 상대 입자 외곽은 가능한 한 160px 이상 떨어뜨리고 최소 64px 밖에 둔다.

금속 묶음은 원래 설계의 R01→R03을 자동 연쇄로 해석하지 않는다. R01 뒤 아연이 남은 조각에 Ag⁺를 가져오면 경쟁 경로다. R03을 보려면 그 조각을 통째로 선반에 놓고, 선반의 순수 구리 조각과 Ag⁺ 둘을 꺼낸다. 생성 Zn²⁺는 R03 허용 맥락이므로 무대에 남겨도 된다. 선반 내용은 처음부터 표시하고 재료를 몰래 없애거나 순수 구리 조각을 생성물로 바꾸지 않는다.

### 3.3 검색과 구조만 보기

검색 이름은 `재료 찾기`다. 한국어 이름·화학식·통상 별칭을 검색한다. 공백, 대소문자, 아래첨자·위첨자는 비교할 때만 정규화한다. 한국어 이름은 부분 일치, 화학식은 전하까지 포함한 전체 일치로 찾는다. `H3O+`, `H₃O⁺`, `하이드로늄`은 같은 결과이고 `Cu2+`는 구리 이온만, `Cu`는 구리 조각만 찾는다. `소금`은 소금 결정, `은`은 은 이온·염화 은 고체·은 조각을 원래 순서로 보여 준다. 결과가 없으면 `찾는 재료가 없어요.`를 표시하고 검색어를 보존한다. 검색 중에는 시작 묶음과 선반을 접어 결과가 바로 보이게 하되 검색을 비우면 원래 상태로 복귀한다. 한글 입력 조합 중에는 Enter를 추가 명령으로 받지 않는다.

단계 1 목록 다음에 엔진이 읽을 수 있는 기존 구조 목록을 `구조만 보기`로 분리한다. 해당 줄마다 같은 배지를 붙인다. 아세트산·K⁺·Br⁻를 단계 1 반응 재료처럼 섞지 않는다. 구조를 선택하면 추가 편집만 하고 배지를 무대의 접근 가능한 입자 이름과 서랍 현재 재료에도 유지한다. 접촉 결과는 `SPECIES_UNREVIEWED` 등 실제 판정에 따른다. 등록되지 않았다는 이유로 부정 판정을 만들지 않는다.

임의 구조는 서랍 안의 `구조 입력` 펼침 영역에서 받는다. 입력 이름은 `화학식 또는 구조 문자열`, 입력 후 Enter로 추가하며 입력 영역 밖에 별도 주 버튼을 만들지 않는다. 입력한 구조는 `구조만 보기`로 시작하고 실제 그래프 대조가 끝난 경우에만 등록 재료로 분류한다. `addSpecies`가 읽지 못하면 `이 구조는 표시할 수 없어요`를 입력 옆에 표시하고 무대를 유지한다. 구조 읽기 성공을 반응 검토 완료로 표시하지 않는다. 조립으로 만든 HCl도 물속에서 자동으로 H₃O⁺와 Cl⁻가 되지 않는다.

### 3.4 대기 선반

선반은 재료 서랍 안의 목록이다. 접혀 있을 때도 이름과 개수, 끌어 놓을 48px 영역을 남긴다. 끄는 동안 결과 서랍이 열려 있었다면 재료 서랍으로 전환해 선반을 드롭 대상으로 노출한다. 안내는 `무대의 반응 검토에서 제외해요.`다. 혼합 금속과 결정은 전체 묶음만 옮길 수 있다.

선반에 놓으면 활성 무대에서 빼고 World·물질 정보·원자 ID를 보존한다. 선반 항목을 고르면 같은 묶음을 빈 자리에 꺼내며 복제하지 않는다. 한도 초과면 그대로 선반에 남는다. 키보드에서도 선택한 입자의 대상으로 `대기 선반`을 고를 수 있다. 선반은 판정 맥락에서 제외하지만 실행 취소·비우기·묶음 교체에는 포함한다. 삭제 기능은 단계 1 필수가 아니며 비우기와 선반으로 정리한다.

## 4. 끌기 상태 기계

### 4.1 공통 계약

화면 상태 흐름은 `idle → dragging → preview → drop → choose / needs-material / preflight / explained → playing → idle`다. `drop`은 이벤트 처리 단계이며 오래 머무는 화면이 아니다. `reviewing`은 과거 장면 다시 보기 전용 상태로 따로 둔다. 상태·화학 판정·실행 준비 상태는 별도 필드다.

분자에서 어느 원자를 잡아도 분자 전체가 움직인다. 결정·금속은 `aggregateId` 전체가 움직인다. 집은 원자 ID와 접촉 자리는 별도로 기록한다. 고체 안 원자 하나를 집었다고 조각에서 떼지 않는다. 끄는 중 좌표는 임시 표시이고 원본 World를 수정하지 않는다.

후보 시작은 외곽 거리 48 CSS px 이하, 120ms 유지다. 기존 후보는 64px 밖으로 나가거나 다른 후보가 12px 이상 가까운 상태가 120ms 지속될 때 바꾼다. 후보 계산은 열운동 좌표가 아니라 저장 좌표와 현재 끌기 이동량을 쓴다. 우선순위는 사용자가 고정한 자리, 거리, 안정 원자 ID다. 이 값들은 UI 기준이며 실제 거리·반응 속도가 아니다.

H₃O⁺·NH₄⁺는 현재 그래프의 결합된 H를 주는 자리, OH⁻의 O·NH₃의 N은 받는 자리다. 동등한 H는 후보 하나로 합치되 선택된 원자 ID를 남긴다. 침전은 자유 이온 둘의 중심, 용해는 선택한 물과 소금 표면 한 쌍, 금속은 표면 원자와 금속 이온 자리다. 배경 물을 클릭해서 D01 손잡이를 대신하지 않는다.

놓는 순간 후보, 환경, 전체 활성 재료, `revision`, 예약 가능 수량을 다시 검사한다. `classifyContact`만으로 최종 제목을 붙이지 않는다. `planEvent`까지의 결과를 쓴다. 같은 제스처에서 pointerup·Enter·중복 이벤트가 와도 하나의 토큰으로 한 번만 실행한다. 후보가 낡았으면 시작 상태로 복원하고 `재료가 바뀌었어요. 다시 골라요.`를 알린다. 자신과의 접촉은 조작하지 않은 것으로 끝낸다.

조합이 여러 개인 것과 화학 경로가 경쟁하는 것은 다르다. 서로 다른 접촉 대상은 고를 수 있다. 같은 재료에서 경쟁하는 경로와 허용되지 않은 제3 재료는 선택 메뉴로 없애지 않는다. `COMPETING_PATHWAYS`·`CONTEXT_UNREVIEWED` 결과를 그대로 보여 준다.

### 4.3 Ag⁺가 하나 모자라는 경우

Zn/Cu 표면 원자 하나와 Ag⁺ 둘이 한 사건이다. 첫 접촉 중심에서 120px 안의 사용 가능한 두 번째 Ag⁺를 거리·ID 순으로 예약한다. 선반·다른 결정·이미 예약된 이온·배경은 세지 않는다. 멀리 있는 Ag⁺를 자동으로 끌어오지 않는다.

부족 대기는 원래 드래그 시작 상태와 임시 접촉 위치를 보관한다. 사용자는 다른 Ag⁺를 가까이 가져오거나 서랍에서 추가한다. 추가는 별도 편집 한 항목이고, 첫 접촉은 아직 미확정이다. 추가 위치는 자동 반응 범위 밖이며 사용자가 다시 끌어 가져와야 한다. 필요한 이온이 모이면 새 revision으로 다시 판정하고 전체 사건을 실행한다.

대기 중 별도 추가가 있었다면 그 편집을 보존한 상태에서 처음 끌던 묶음의 원래 위치를 반영한 스냅샷을 새 사건 시작점으로 삼는다. 따라서 완료 후 실행 취소 한 번은 반응·접근만 취소하고, 그다음 한 번은 추가를 취소한다. Esc도 별도 추가를 지우지 않는다. 실행 취소를 대기 중 누르면 먼저 미확정 접촉만 취소하고 기록 항목은 다음 누름에서 처리한다. UI가 임의의 중간 Zn⁺·Cu⁺를 저장하지 않는다.

자세히에는 공통 두 문장 다음에 부족 수량을 그대로 적는다. 추가 설명은 `이 화면에서는 은 이온 둘이 전자를 하나씩 받는 모습을 한 번에 그려요. 실제 반응이 은 이온 둘을 기다리며 멈춘다는 뜻은 아니에요.`다. 이는 수량 제한을 쉬운 말로 풀어 쓴 새 조작 안내이며, 자료 행의 화학 결과 문구를 바꾼 것이 아니다.

### 4.4 키보드

Tab 순서는 앱 탭 → 모드 → 보기 설정 → 무대 입자 → 설명 줄 → 조작 줄 → 서랍이다. 입자가 많으면 무대 안에서 roving tabindex를 쓰고 좌우 방향키로 안정 인스턴스 순서를 순회한다. 선택 이름은 예를 들어 `은 이온 Ag⁺, 2번`이고 고체는 `아연 조각, 원자 6개`다. 개별 고체 구성원을 자유 입자로 읽지 않는다.

1. 재료 줄에서 Enter/Space로 한 번 추가한다. 무대에서는 Enter/Space로 입자를 선택한다.
2. 주 버튼 `다가갈 대상 고르기`를 누르면 서랍에 대상 목록과 `대기 선반`이 나온다. 방향키로 목록을 이동하고 Enter/Space로 선택한다.
3. 다른 반응 자리가 필요하면 Tab으로 허용 자리 고리를 순회한다. 동등한 H는 기본 하나이고 필요할 때 선택한 H를 고정한다. 서랍에도 같은 자리 이름을 표시한다.
4. 주 버튼 `접촉하기` 또는 Enter로 포인터 놓기와 같은 검사를 실행한다. 가까이 놓는 배치는 화면 계층이 계산하되 재료 수·맥락 검사를 생략하지 않는다.
5. 위치만 옮기려면 선택 후 Space로 이동 상태를 시작한다. 방향키는 8 CSS px, Shift+방향키는 1px씩 옮기며 Enter로 놓고 Esc로 취소한다. 이 상태에서는 방향키를 입자 순회에 쓰지 않는다.

Ctrl/Cmd+Z는 실행 취소, Ctrl/Cmd+Shift+Z와 Windows Ctrl+Y는 다시 실행이다. 검색·구조 입력 등 텍스트 편집에 포커스가 있으면 브라우저의 텍스트 편집을 우선한다. Esc는 끌기·선택·부족 대기·재생 취소, 자세히에서만 접기다. 포커스가 어느 상태에 있는지에 따라 한 번에 한 동작만 한다.

설명 줄은 `aria-live="polite"`로 최종 상태 변화만 알리고 120ms마다 같은 문장을 반복하지 않는다. 실패는 한 번 즉시 알린다. 재생 종료는 생성물, 취소는 원래 입자, 자세히 접기는 자세히 버튼으로 포커스를 돌린다. hover 전용 정보는 포커스에서도 나온다.

### 4.5 주 버튼과 입력 오류

주 버튼은 아래에서 현재 상태에 맞는 첫 행 하나만 쓴다. `자세히`는 설명 줄, `접기`는 상세 서랍에 있으므로 주 버튼 수에 더하지 않는다. 재료 서랍을 여는 `재료 고르기`는 재료를 자동 추가하지 않는다. 이미 열려 있으면 검색으로 포커스를 옮기고, 부족 대기에서는 필요한 재료 줄로 옮긴다.

| 우선순위·상태 | 주 버튼 | 누른 뒤 |
|---|---|---|
| 1. 다시 보기 | 다시 보기 끝내기 | 현재 편집 상태로 복귀한다 |
| 2. 새 사건 재생 | 건너뛰기 | 검증한 끝 상태를 한 번 확정한다 |
| 3. 사전 검사·포인터 끌기 | 접촉하기(비활성) | 포인터 놓기 또는 검사 완료를 기다린다 |
| 4. 대상 고르기 | 접촉하기 | 후보 하나를 고른 뒤에만 활성화한다 |
| 5. 부족·부정·모름·실행 실패 | 재료 고르기 | 재료 서랍으로 이동한다 |
| 6. 새 입자를 선택함 | 다가갈 대상 고르기 | 대상 목록을 연다 |
| 7. 성공 직후 또는 기록의 재생 가능한 사건 선택 | 다시 보기 | 저장한 타임라인을 재생한다 |
| 8. 빈 판·선택 없음·재생할 사건 없음 | 재료 고르기 | 재료 서랍으로 이동한다 |

`input-error`는 결과 카드와 구분한다. 진행하던 임시 이동만 취소하고 확정 재고는 유지한다. 아래 문구는 이번 명세의 조작 안내다. 입력 오류를 부정·모름 사건으로 기록하지 않는다.

| `reason` | 설명 줄 | 다음 조작 |
|---|---|---|
| SAME_TARGET | 별도 안내 없음. 직전 안내 유지 | 자기 자신 또는 같은 고체 내부의 접촉을 무시한다 |
| STALE_CANDIDATE | 재료가 바뀌었어요. 다시 골라요. | 낡은 후보를 버리고 현재 무대를 보여 준다 |
| UNAVAILABLE_TARGET | 지금은 이 재료를 고를 수 없어요. | 예약 중이거나 선반에 있는 대상을 선택 해제한다 |
| INVALID_INPUT | 재료 정보를 읽지 못했어요. 다시 골라요. | 현재 저장소에서 요약을 다시 만들고 재선택하게 한다. 같은 오류가 나면 재생하지 않는다 |

포인터 캡처 손실·창 포커스 이탈은 끌기·미리보기만 취소한다. 재생이 시작된 뒤 창을 전환했다는 이유로 화학 상태를 취소하거나 다시 적용하지 않는다. 재생 취소는 `실행 취소` 또는 Esc로만 한다.

## 5. 분자 조립 조작

서랍은 `수소 H`, `탄소 C`, `질소 N`, `산소 O`, `플루오린 F`, `염소 Cl` 순으로 원자 모형을 제공한다. 원자 모형 하나씩 넣고, 두 원자의 홑전자가 하나씩 남아 있을 때 결합을 하나 만든다. 이 전자 배치는 실제 낱원자 상태라는 주장이 아니다. `pulls`는 끈다.

새 결합은 서로 다른 연결 묶음에서만 만든다. 기존 두 원자 사이 결합은 선택 후 주 버튼 `결합 하나 더 잇기`로 1→2→3만 올린다. 같은 분자 안에서 새로 이어 고리를 만들지 않는다. 분자 전체를 끄는 동작과 결합 양 끝 원자를 고르는 동작은 구분한다. 선택 원자 두 개와 남은 홑전자만 고리로 표시하고 검사가 허용되기 전에 주머니를 만들지 않는다.

조립판에서 원자 클릭 또는 Enter는 첫 원자 선택이다. 다른 원자를 클릭하거나 방향키로 포커스를 옮겨 Enter를 누르면 둘째 원자를 고른다. 고른 원자에는 1·2 고리를 붙인다. 같은 원자를 다시 고르면 그 선택만 해제한다. 두 원자를 골랐을 때 주 버튼은 새 결합이면 `결합 잇기`, 기존 결합이면 `결합 하나 더 잇기`다. 검사에서 막아도 버튼을 누르면 차단 이유를 읽을 수 있고 판은 바뀌지 않는다. Esc는 두 원자 선택만 해제한다. 빈 판의 `원자 고르기`는 원자 서랍으로 포커스를 옮긴다.

포인터를 4px 넘게 움직이면 클릭 선택 대신 전체 연결 묶음 끌기를 시작한다. 처음 집은 원자가 결합 후보의 한쪽 끝이고, 상대 원자를 고리로 표시한다. 놓을 때 이 두 원자로 한 번 검사한다. 후보가 없는 곳에 놓으면 위치만 바꾼다. 키보드는 원자 선택 후 Space로 묶음 이동, 방향키·Enter·Esc로 4.4절과 같이 조작한다. 조립 중 두 원자 선택이 있으면 완성 구조의 `반응 재료로 넣기`보다 결합 버튼을 우선한다. 선택을 풀면 해당 연결 성분의 결과 버튼으로 돌아간다.

수용액의 상태 기계를 재사용하되 `classifyContact` 대신 `checkAssemblyBond`를 호출한다. 놓기/Enter에서는 `createAssemblyStep`의 검사를 다시 거친다. 차단되면 원래 판을 유지하고 반환 문구를 설명 줄·자세히에 표시한다. 성공은 조립 한 단계이며 실제 물질 생성 반응으로 이름 붙이지 않는다. 결합을 늘린 뒤 선택한 연결 성분 하나만 `evaluateAssembly`로 대조한다.

O 둘의 첫 단일 결합은 허용하고 O=O 완성은 막는다. 다른 곳에 H를 놓아도 막는다. H–O–O–H와 O=C=O는 허용한다. 조립 결과 가운데 물과 암모니아만 `반응 재료로 넣기`를 활성화한다. 아세트산 등 이름이 붙는 구조도 단계 1 반응 재료는 아니다. 조립 작업판 한도는 전체 원자 24개로 정하고, 수용액의 종류별 6단위를 적용해 에탄올의 H 6개 등을 잘못 막지 않는다.

## 6. 결과 카드와 문구

### 6.1 위치·공통 내용·양성 결과

접힌 결과 카드는 설명 줄의 제목 하나와 `자세히`다. `자세히`를 누르면 오른쪽 서랍이 `결과`로 바뀐다. 상세 바닥의 `접기`는 이전 서랍 내용과 포커스를 복원한다. 이때 설명 줄의 자세히 버튼은 숨겨 같은 상세를 두 군데서 접지 않는다. 다른 결과로 갱신되면 열린 서랍의 제목·내용도 함께 바뀐다.

수용액 결과 상세의 첫 두 문장은 언제나 **“화면의 입자는 수많은 입자를 대표해요. 입자 수는 농도나 반응한 비율이 아니에요.”**다. 그 뒤 아래 문장을 그대로 붙인다. 당시 조건, 실제 참여 재료·개수, 출처 링크와 자료 대조 상태를 내용 항목으로 둔다. 숫자 ID·엔진 오류 전문은 사용자가 요청한 진단 내용에만 둔다.

| 사건 | 결과 제목 | 자세히에 덧붙일 원문 |
|---|---|---|
| A01 | 물 분자 둘이 되었어요. | H₃O⁺의 수소 하나를 OH⁻가 받았어요. 수소가 옮겨지고 두 산소에 전자쌍이 남는 모습을 보여 줘요. |
| A02 | 암모늄 이온이 되었어요. | 암모니아의 질소가 H₃O⁺에서 수소 하나를 받았어요. H₃O⁺는 물이 되었어요. |
| A05 | 암모니아와 물이 되었어요. | OH⁻가 암모늄 이온에서 수소 하나를 받았어요. 이 방향의 반응을 보여 줘요. 실제로 남는 비율은 계산하지 않아요. |
| P01 새 고체 | 염화 은 고체가 생겼어요. | Ag⁺와 Cl⁻가 전하를 그대로 가진 채 고체에 모였어요. 작은 판은 고체의 한 부분을 나타내요. 실제 결정이 생기는 속도나 녹아 남는 양은 계산하지 않아요. |
| P01 기존 고체 | 염화 은 고체가 커졌어요. | Ag⁺와 Cl⁻가 전하를 그대로 가진 채 고체에 모였어요. 작은 판은 고체의 한 부분을 나타내요. 실제 결정이 생기는 속도나 녹아 남는 양은 계산하지 않아요. |
| D01 | 소금에서 이온 한 쌍이 나왔어요. | Na⁺와 Cl⁻가 결정에서 나와 물에 둘러싸였어요. 물 분자가 소모되는 반응은 아니에요. 녹을 수 있는 총량은 계산하지 않아요. |
| R01 | 구리가 붙고 아연 이온이 나왔어요. | 아연이 내준 전자 두 개를 구리 이온이 받아 금속이 되었어요. 점은 전자가 옮겨가는 수를 보여 줘요. 실제 이동 경로나 반응 속도는 나타내지 않아요. |
| R02 | 은이 붙고 아연 이온이 나왔어요. | 아연이 내준 전자를 은 이온 둘이 하나씩 받았어요. 은은 금속 표면에 붙고 아연 이온은 물속으로 나왔어요. 점은 이동한 전자 수를 나타내요. |
| R03 | 은이 붙고 구리 이온이 나왔어요. | 구리가 내준 전자를 은 이온 둘이 하나씩 받았어요. 은은 금속 표면에 붙고 구리 이온은 물속으로 나왔어요. 점은 이동한 전자 수를 나타내요. |

위 제목은 실행 성공 뒤에만 쓴다. 기존 고체 성장 제목은 실제 `effects`가 기존 판에 더했음을 확인한 뒤에만 쓴다. 미리보기·부족·사전 검사에서 완료형을 쓰지 않는다. 양성 결과의 버튼은 설명 줄 `자세히`, 조작 줄의 유일한 주 버튼 `다시 보기`, 상세 서랍 `접기`다. 입자를 새로 선택하면 주 버튼은 `다가갈 대상 고르기`로 바뀌고, 다시 보기는 기록에서 해당 사건을 고를 때 같은 자리로 돌아온다.

### 6.2 검토된 부정

다음은 자료 행의 제목·설명을 그대로 옮긴 것이다. 공통 두 문장 뒤에 상세를 붙인다. 해당 두 종류와 물 이외 재료가 있으면 부정 인증을 무조건 적용하지 않고 전체 맥락을 다시 검사한다. 모든 행의 버튼은 `자세히`, 주 버튼 `재료 고르기`, 상세 `접기`다. 재생할 사건이 없으므로 이 결과에 대한 다시 보기는 없다.

| 인증 | 제목 | 자세히에 덧붙일 원문 |
|---|---|---|
| N01 | 소금 결정으로 뭉치지 않아요 | 이 묽은 물속에서는 두 이온이 따로 남아요. 농축하거나 물을 말리는 경우는 다루지 않아요. |
| N07 | 두 이온은 따로 남아요 | 이 조건에서는 Na⁺와 OH⁻를 한 분자로 묶지 않아요. |
| N09 | 이온으로 남아요 | 이 묽은 물속에서는 H₃O⁺와 Cl⁻로 나타내요. 순간적인 만남까지 없다는 뜻은 아니에요. |
| N12 | 두 이온은 따로 남아요 | NH₄⁺와 Cl⁻를 한 분자나 결정으로 묶지 않아요. NH₄⁺와 물 사이의 평형은 따로 계산하지 않아요. |
| N15 | 아연 금속이 생기지 않아요 | 이 참고 조건에서 구리가 아연 이온을 아연 금속으로 바꾸는 방향은 지지되지 않아요. |
| N16 | 아연 금속이 생기지 않아요 | 이 참고 조건에서 은이 아연 이온을 아연 금속으로 바꾸는 방향은 지지되지 않아요. |
| N17 | 구리 금속이 생기지 않아요 | 이 참고 조건에서 은이 구리 이온을 구리 금속으로 바꾸는 방향은 지지되지 않아요. |
| N21 | 염화 이온으로 남아요 | 물이 주변을 둘러쌀 수 있지만, 이 조건에서 가수분해로 바뀌는 양은 무시할 수 있어요. |
| N22 | 나트륨 이온으로 남아요 | 물이 주변을 둘러싸도, 이 조건에서는 산·염기 반응으로 새 물질이 생기는 것으로 다루지 않아요. |
| N23 | 나트륨 이온은 중화에 참여하지 않아요 | Na⁺가 H₃O⁺의 수소를 받아 중화하는 반응은 없어요. 물의 움직임이나 수소 교환까지 없다는 뜻은 아니에요. |
| N24 | 두 이온은 서로 중화하지 않아요 | Cl⁻는 OH⁻와 만나 물을 만드는 산으로 작용하지 않아요. 이 묽은 물속에서 HCl 분자로 바꾸어 그리지 않아요. |
| N25 | 나트륨 이온은 이 반응에 참여하지 않아요 | Na⁺가 암모니아에 수소를 주거나 받는 반응은 없어요. 암모니아와 물은 일부 반응할 수 있지만, 그 비율은 계산하지 않아요. |
| N26 | 나트륨 이온 둘로 남아요 | Na⁺ 둘을 중성 분자나 소금 결정으로 묶지 않아요. 주변 물과의 상호작용은 있을 수 있어요. |

| CONTEXT_UNREVIEWED / COMPETING_PATHWAYS | 함께 있는 재료 때문에 판단할 수 없어요. |
| EQUILIBRIUM_REQUIRED | 얼마나 반응하는지는 계산하지 않아요. |

상세는 공통 두 문장, 위 문장, 해당 재료·조건 항목 순이다. `함께 있는 재료`에는 실제로 검사한 활성 재료를 적고 선반 재료는 포함하지 않는다. 모든 모름 결과의 버튼은 `자세히`, 주 버튼 `재료 고르기`, 상세 `접기`다. 지원하지 않는 조건 입력을 받으면 조건 표시도 실제 입력으로 표시하고 고정 기본값으로 위장하지 않는다. 조건을 고치는 UI는 단계 1에 추가하지 않는다.

문구 충돌 처리: 자료의 120쌍 표와 현재 `CONTACT_ROWS.detail`은 설계 설명인 “~다” 문장이다. 화면 해요체와 원문 유지 조건을 동시에 지키기 위해 이 문자열을 결과 본문에 직접 붙이지 않는다. 새 해설을 임의로 번역하지 않고 위의 합의된 문장과 재료·조건 항목을 쓴다. 구체적 사유 원문은 상세의 출처 링크로 해당 자료 행을 연결한다. 120행별 해요체 해설이 필요하면 별도 문구 대조 대상으로 남긴다. UI에 `PlannedResult.detail`을 무조건 출력하는 구현은 금지한다.

### 6.4 재료 부족·실행 실패·자료 대조 전

| 종류 | 제목 | 자세히 내용 | 버튼 |
|---|---|---|---|
| 수량 부족 | Ag⁺ 1개가 더 필요해요 | 공통 두 문장, 필요한 Ag⁺ 둘/현재 하나, 4.3절 수량 제한 설명. 실제 위치가 먼 입자와 아예 없는 경우를 구분한다 | 자세히 / 주 버튼 재료 고르기 / 상세 접기 |
| RULE_CONFLICT / REPRESENTATION_UNAVAILABLE·끝 상태 불일치 | 장면을 정확히 만들지 못했어요. | 공통 두 문장, 동일 실패 문장, 실패한 단계 항목. 기술 정보는 펼쳐 보는 진단 내용에 둔다 | 자세히 / 주 버튼 재료 고르기 / 상세 접기 |
| 자료 대조 전 실행 차단 | 장면을 정확히 만들지 못했어요. | 공통 두 문장과 `자료 대조: 진행 중` 항목. 화학적 모름이나 검토된 부정으로 바꾸지 않는다 | 위 실패와 같음 |

실패하면 반응 시작 스냅샷을 복원한다. 성공 카드·생성물·전자 이동을 먼저 보여 준 뒤 취소하는 방식으로 처리하지 않는다. 부정 인증도 아직 draft면 공개 화면에서 “검토된” 결과로 확정하지 않는다. 개발 인수 장면의 자료 사용과 공개 실행 경로를 분리한다.

출처에는 실제 대조 완료 자료에만 **“출처와 대조한 자료이고 전문가가 검토한 것은 아니에요.”**를 쓴다. 지금 draft 자료에 이 문장을 붙여 대조가 끝난 것처럼 보이지 않게 한다. 자료·엔진 버전은 상세 기록에 보존하되 첫 화면에 개발 정보를 늘어놓지 않는다.

### 6.5 조립 결과

조립 결과에는 수용액의 공통 두 문장과 조건을 붙이지 않는다. 상세 첫 문장은 `원자 모형을 연결해 분자 구조를 조립해요.`다. 이어 아래 원문과 선택 구조 그림을 둔다.

| 결과 | 원문 | 제목 배치·버튼 |
|---|---|---|
| 등록 구조와 같음 | 물 분자 모형을 조립했어요. | 이름만 `ASSEMBLY_MOLECULES.message`로 대체한다. 물·암모니아면 주 버튼 `반응 재료로 넣기`, 나머지는 `원자 고르기`. 자세히 / 상세 접기 |
| 짝지어졌으나 목록 밖 | 전자 표시는 모두 짝지어졌어요. 실제로 있는 분자인지는 아직 확인하지 않았어요. | 설명 줄 제목은 첫 문장, 상세에는 두 문장 그대로다. 주 버튼 원자 고르기 / 자세히 / 상세 접기 |
| 홑전자 남음 | 이 모형에는 짝을 이루지 않은 전자가 남아 있어요. | 원문 그대로 제목. 주 버튼 원자 고르기 / 자세히 / 상세 접기 |
| O₂ 완성 차단 | 산소 분자의 실제 홑전자 두 개는 이 조립 모형으로 정확히 나타낼 수 없어요. | 원문 그대로, 별도 꼬리표 없이 60자 이내로 표시한다. 주 버튼 원자 고르기 / 자세히 / 상세 접기 |
| 기타 결합 차단 | `ASSEMBLY_BLOCK_MESSAGES`의 해당 문구 | 5절의 조작 검사에서 받은 문장. 주 버튼 원자 고르기 / 자세히 / 상세 접기 |
| 조립 실행 실패 | 장면을 정확히 만들지 못했어요. | 화학 결과 셋과 구분한다. 시작 조립판 복원. 주 버튼 원자 고르기 / 자세히 / 상세 접기 |

상세를 열었다는 이유로 조립·반응을 재실행하지 않는다. 완료 구조가 여럿이면 선택한 연결 성분만 결과로 표시한다. 조립판 전체의 분자식을 합쳐 하나의 이름을 찾지 않는다.

## 7. 실행 취소·다시 실행·다시 보기·비우기

| 표시 이름 | 위치·활성 조건 | 동작 |
|---|---|---|
| 실행 취소 | 조작 줄 왼쪽 아이콘. 기록이 있거나 취소할 미확정 조작이 있을 때 활성 | 먼저 진행 중 제스처를 취소한다. 확정 항목은 바로 앞 시작 스냅샷을 복원한다. 재생 중이면 그 사건 전체를 취소한다 |
| 다시 실행 | 조작 줄 두 번째 아이콘. 취소한 기록이 있을 때 활성 | 저장한 끝 상태를 그대로 복원한다. 판정·컴파일·난수를 다시 실행하지 않는다 |
| 다시 보기 | 성공 결과 또는 기록에서 재생 가능한 사건을 선택했을 때 오른쪽 주 버튼 | 저장 타임라인만 재생한다. 지금 무대·선반·재고·기록을 별도로 보관하고 끝나면 복원한다 |
| 비우기 | 재료 서랍 바닥의 글자 버튼. 현재 모드에 재료가 있을 때 활성 | 현재 모드의 활성 재료와 선반 전체를 비우고 선택·후보·결과를 해제한다. 배경과 고정 조건은 유지한다. 한 항목으로 기록한다 |

비우기에는 확인창을 두지 않는다. 설명 줄에 `재료를 비웠어요.`를 표시하고 실행 취소로 전체를 복구한다. 다른 모드의 판은 비우지 않는다. 비운 뒤 기록은 남고 그 기록에서 과거 장면을 다시 볼 수 있다.

재료 추가, 시작 묶음 교체, 단순 이동, 선반 이동, 조립 결합 하나, 성공한 반응 하나가 각각 한 항목이다. 부정·모름 접촉은 화학 변화 없이 위치가 달라졌으면 위치와 결과 변경을 한 항목으로 남긴다. 미리보기만 본 경우, 실패, 검색, 상세 펼침, 모드 전환은 새 편집 기록이 아니다. 조립→반응 재료 추가는 목적 모드의 편집 한 항목이다.

각 모드별 최근 100항목을 메모리에 보관한다. 새 편집이 확정되면 해당 모드의 다시 실행 가지를 지운다. 기록은 World/조립판, 인스턴스·고체 묶음, 선반, 이름 발급 상태, 결과, 당시 조건, 자료·엔진 버전, 재생 타임라인을 함께 보관한다. 복원해도 `revision`은 증가한다. 원자 ID는 그대로지만 이전 후보 손잡이를 재사용하지 않는다.

재생 중에는 실행 취소·건너뛰기만 화학 상태를 바꿀 수 있다. 첫 전자 이동 뒤 실행 취소해도 Zn⁺·중성 Ag 하나가 남지 않는다. 건너뛰기는 검증한 끝 상태를 한 번 확정한다. 다시 보기 중 실행 취소·다시 실행·비우기는 비활성이고 종료만 가능하다. 움직임 줄이기 환경에서는 연속 움직임 대신 검증한 단계 끝 그림을 보여 주며, 중간 상태를 편집 가능한 재고로 만들지 않는다.

### 8.1 수용액 실행 연결

1. 표시용 이름이 아니라 실제 그래프·전하·상·고체 구성원으로 현재 재료를 대조한다. `MaterialRef`는 금속 표면 원자 하나/결정 조성 한 단위이고, 잡아서 이동하는 대상은 전체 `aggregateId`다. 이 두 단위를 섞지 않는다. 그래프 대조·고체 구성 관리 연결부는 아직 추가할 일이다.
2. `classifyContact(a, b, environment)`는 조건부 후보만 돌려준다. 이어 `planEvent(candidate, scene)`를 호출한다. 활성 고체 구성원은 `aggregates`에만 넣고 `particles`에 중복하지 않는다. 선반과 배경 물은 활성 재고에서 제외한다. 필요한 `capabilities`, `freeBackgroundWaterCount`는 실제 연결 상태를 확인한 값이어야 한다.
3. `readiness.kind === 'preflight'`에서도 바로 재생하지 않는다. 계획의 `canExecute: false`를 덮어쓰지 않고, 별도의 실행 승인 결과를 만든다. 자료 대조, 현재 revision, 실제 예약 원자, 지원 명령, 원자 매핑·전하·모형 전자 수·기대 생성물 검사를 한다.
4. `lab-rows-stage1.md` 7절의 사건 템플릿에 현재 원자 ID와 고체 이름을 넣는다. 템플릿을 생성하는 범용 함수는 현재 `src/lab/`에 없다. `lab-run.ts`에 사건 여덟 개의 명시적 연결을 만들고 기획 ID를 기준으로 검사한다. owner 이름에서 새 H 이름을 만들지 않는다.
5. E1 `compileFrom(base, stage, steps, opts)`에는 `step` 블록만 넘긴다. `errors`가 있거나 timeline/end가 없으면 전부 폐기한다. E1이 반환한 `end`를 계획과 대조한 뒤에만 재생한다. 표시 타임라인의 중간 World를 저장소로 쓰지 않는다.
6. E2는 함수가 아니라 대본 `precipitate using a b [onto s]`다. 선택된 자유 이온의 실제 선언 참조를 쓰고, `onto`는 계획에 있는 순수 AgCl 묶음만 쓴다. 새 고체 이름·기존 고체 성장 여부는 `effects`로 받는다. 자료 `EVENT_BY_ID.P01.title`과 `EVENT_BY_ID.P01.ontoTitle`을 구분한다. `EVENTS`는 배열이므로 `EVENTS.P01`로 접근하지 않는다.
7. 금속은 `land` → `hop` 두 번 → `join`·`leave` 템플릿을 사용한다. `land` 중 같은 엔진 결정 목록에 들어간 양이온을 이미 금속이 된 것으로 분류하지 않는다. 고체상의 확정은 끝 상태 대조 뒤에 한다. 표면 기능이 연결되지 않았으면 실행 실패다.
8. 원자 ID별 원소, 전체 참여 원자, 총전하, 모형 전자 수 `2Σlp + Σrad + 2Σ결합 차수`, 생성물 그래프·상·고체 소속, 무관한 입자 불변을 대조한다. 수화용 배경 물의 생성·이동은 별도 표현 기록으로 구분한다. 이 검사는 UI 연결부에 추가해야 하며 현재 판정 함수가 이미 보장한다고 가정하지 않는다.
9. 끝 상태를 한 번 확정하고 새 인스턴스를 발급한다. 이전 원자 ID와 연결하되 revision을 높인다. 생성물의 다음 접촉은 새 그래프에서 판정한다. 자동 연쇄 반응은 없다.

고체 재료 추가는 단순 `addSpecies('NaCl')`·`addSpecies('Zn')`만으로 끝내지 않는다. 실제 구성원 ID와 고체 소속이 필요하다. 재료 계층에서 임시 World에 안전하게 만들고 이름 충돌·장부를 검사한 뒤 전체를 병합하는 연결을 별도로 작성한다. E1 안에서 `metal`·`crystal` 생성 명령을 호출하지 않는다. 기존 무대를 새 전체 대본으로 컴파일해 위치·ID를 재발급하지 않는다.

### 8.2 조립과 그리기 연결

`createAssemblyHeader(board)`가 반환하는 `.world`를 현재 조립판 복사본으로 사용한다. C·N·O의 조립용 전자 배치를 일반 단원자 SMILES로 바꾸지 않는다. `mode: 'world'`는 지원하는 정상 경로다. `createAssemblyStep(graph, a, b)`가 허용한 script만 `compileFrom`에 넘기고 반환 graph와 끝 World를 대조한다. 원자 배열 순서를 보존해 `a0.H` 등의 ID가 바뀌지 않게 한다. 연결 성분을 결과 검사에 넘길 때만 별도 인덱스로 대조하고 실제 판 ID는 바꾸지 않는다.

현재 `Stage.load(script)`는 `compile`을 호출하므로 이어지는 반응에 쓰지 않는다. 새 어댑터에서 `StageView.setTimeline`과 `Player.load`를 호출하고, 기존 Stage의 tl·lens·배경 설정을 일관되게 연결하는 진입점을 마련한다. `Stage.world`는 단계 끝 상태이므로 끌기 저장소의 원본으로 삼지 않는다. `Stage.pick` 결과도 전체 분자·고체 소속으로 다시 올려 선택한다.

공유 결합은 전자쌍 주머니, 반응 중 이동 전자는 같은 점으로 이어 그린다. 결정은 첫 쌍부터 각진 판 하나, 이온 전하 유지, 공유 주머니 없음이다. 금속은 추적 원자 6개 전체 표면, 반응 자리에서 드러난 두 점, 전자별 전하 변화, 붙은 금속과 빠져나온 이온이다. 그림에서 전자를 생략해도 장부에서 없애지 않는다.

`look: 'color'`를 구현 검증 기준으로 잡되, `glow` 검토 화면에서도 고리·선택·결과가 색에 기대지 않는지 별도로 본다. 붉은빛/푸른빛을 성공·실패 신호로 쓰지 않고, 빛을 깜빡이거나 반응 준비 표시로 쓰지 않는다. 이 검토는 표현 채택 결정을 대신하지 않는다.

### 8.3 현재 API와 반환값 연결표

| 현재 파일·API | 화면에서 넘기는 것·받은 뒤 할 일 |
|---|---|
| `src/lab/stage1-data.ts`: `MATERIALS`, `MATERIAL_BY_ID`, `EVENTS`, `EVENT_BY_ID` | 앞의 둘은 재료 배열/ID 조회, 뒤의 둘은 사건 배열/ID 조회다. 한국어 재료 이름과 시작 묶음은 3절의 화면 자료로 별도 관리한다 |
| 같은 파일: `NUMERIC_ROWS`, `SOURCE_ROWS`, `DERIVED_ROWS`, `CONTACT_ROWS`, `DATA_VERSION`, `REVIEW` | 출처·대조 상태·기록에 연결한다. `deriveStage1Numbers()`는 고정 참고 자료 계산이며 화면 입자 수를 농도로 환산하는 함수가 아니다 |
| `src/lab/judge.ts`: `classifyContact(a, b, env)` → `ContactResult` | 현재 `MaterialRef` 둘과 고정 환경을 넘긴다. `contact` 스냅샷을 보존하고 조건부 결과를 다음 함수에 넘긴다 |
| 같은 파일: `planEvent(candidate, scene)` → `PlannedResult` | `kind`로 먼저 분기한다. `reacts`일 때만 `readiness.kind`를 읽는다. 부족은 `readiness.missing`, 사전 검사는 `readiness.plan`이다. 최상위 `missing`·`plan`을 가정하지 않는다 |
| 같은 파일: `unknownMessage(reason)` | 6.3절 네 제목 중 문자열 하나를 얻는다. 상세를 반환하는 함수는 아니다. `planEvent`의 상세에는 공통 두 문장이 이미 붙어 있으므로 한 번 더 붙이지 않는다 |
| `src/engine/compile.ts`: `addSpecies(base, formulaOrSmiles, name, at)` | 성공의 `world`·`addedAtomIds`만 함께 반영한다. `errors`가 있으면 추가하지 않는다. 이름은 표시 이름과 별도로 발급하고 기존 원자·선언·고체 이름과 충돌하지 않게 한다 |
| 같은 파일: `compileFrom(base, stage, steps, opts?)` | `timeline`, `end`, `effects`, `errors`, `warnings`를 받는다. 컴파일 성공과 실행 승인·끝 상태 대조 성공을 구분한다. 경고를 오류처럼 자동 분류하지 않고 해당 표현을 검토한다 |
| `src/engine/world.ts`: `cloneWorld(world)` | 사건 시작·끝·다시 보기용 World를 복사한다. 인스턴스·선반·결과·예약 등 화면 상태는 별도로 깊게 복사한다 |
| `src/lab/assembly-data.ts`: `createAssemblyGraph(elements, bonds?)` | 조립용 전자 수를 갖춘 그래프를 만든다. 좌표는 별도 `AssemblyBoard` 원자에 붙인다 |
| 같은 파일: `checkAssemblyBond(graph, a, b)` | `a`, `b`는 원자 ID 문자열이 아니라 그래프 배열 인덱스다. `allowed: false`의 `message`를 표시한다. 잘못된 인덱스·동일 원자 예외는 조작 오류로 처리한다 |
| 같은 파일: `evaluateAssembly(graph)` | 선택 연결 성분 하나만 넘긴다. `matched`의 `molecule.id`가 `H2O`이면 `water`, `NH3`이면 `ammonia`로 명시적으로 연결한다. 빈 판·여러 성분 전체를 넘기지 않는다 |
| `src/lab/assembly-script.ts`: `createAssemblyHeader(board)` | 항상 반환하는 `world`·`atomIds`를 사용한다. `mode: 'world'`와 `script: null`은 복원 경로이며 사용자에게 실행 실패로 표시하지 않는다 |
| 같은 파일: `createAssemblyStep(graph, a, b)` | `allowed: true`일 때만 `script`·`graph`가 있다. script를 E1에 넘기고 실제 끝 상태를 예상 graph와 대조한다. 호출 자체로 조립판을 확정하지 않는다 |

`SceneSummary.capabilities`는 실제 연결한 기능만 넣고 각 사건의 `requiredCapabilities`와 대조한다. 추가 Ag⁺의 `distancePx`는 접촉 중심에서 잰 CSS px다. `selectedHydrogenId`에는 화면에서 고른 현재 H ID를 넣는다. P01의 기존 판을 명시한 경우 `ontoAggregateId`, 자동 선택할 때에는 `aggregateDistancesPx`를 넣는다. `freeBackgroundWaterCount`는 실제 자유 배경 물 수이며 보기용 물 무늬가 있다는 이유로 임의 양수를 넣지 않는다.

수용액 결과 본문은 한 계층에서만 조립한다. 양성·부정은 판정기가 반환한 원문 상세를 그대로 쓰고, 모름은 6.3절 정책으로 구성한다. 부족 안내는 아직 일어나지 않은 사건의 `title`·`detail`을 출력하지 않고 `missing[].message`를 먼저 쓴다. 조립 함수가 던진 예외 전문도 그대로 화면에 내보내지 않는다.

## 10. 구현 전 Claude가 검토할 판단

1. **배치 규칙의 충돌**: R4와 합의된 무대 안내를 예약 안내 줄로 함께 지켰다. R8·조작 줄 버튼 셋 제한을 위해 비우기는 서랍, 다시 보기는 상황별 주 버튼으로 배분했다. `ui.md`의 예전 실험실 버튼 예시를 그대로 네 버튼으로 늘리지 않는다.
2. **금속 시작 묶음**: R01 생성 구리를 곧바로 R03에 쓰는 경로는 합의와 맞지 않는다. 순수 구리·은 이온을 선반에 미리 제공하고 사용자가 혼합 조각을 옮기도록 정했다.
3. **문구 원문과 말투**: 양성 여덟 사건·성장 제목·부정 13종·모름 네 문장은 그대로 썼다. 조합표 120행 가운데 모름 99행의 설계 문장을 화면에 복사하지 않는 상세 정책을 6.3절에 명시했다. 긴 조립 문장은 원문 문장 경계에서 제목/상세로 나눴다. 새 수량 안내·입력 오류 안내와 한도 초과 생성물 보존은 화면 연결을 위해 이번에 정했다.
4. **아직 없는 연결**: World에서 재료를 대조하는 계층, 고체 추가·보관, 실행 승인·끝 상태 대조, 사건 대본 생성, 준비된 Timeline 연결, 기록은 새 구현이 필요하다. 현재 순수 판정 함수와 E1/E2만으로 화면 전체가 완성됐다고 보지 않는다.
5. **미완료 검증**: 자료는 draft이고 반응 표현 2.2절은 미확정이다. 이 명세의 인수 시험은 미실행이다. Claude의 원문 대조와 실제 중간 그림·움직임 검증을 각각 남겨야 한다.
